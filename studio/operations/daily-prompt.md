AI 실전노트의 조사·대본·영상·업로드 대기열을 처리하라. AGENTS.md, skills/content-studio/SKILL.md, channels/ai/channel.json, channels/ai/launch/README.md를 먼저 읽어라. AI 채널 하루 3편을 목표로 하며 퀴즈 채널은 운영하지 않는다.
work-cases/의 사용자 실제 작업과 남은 문제를 먼저 확인하라. 공식 GitHub·Hugging Face·제품 문서와 커뮤니티의 새 활용법은 그 작업에 적용할 후보로 조사하고 원문과 확인일을 기록하라. 필요한 일을 실제 수행해 산출물과 검사·실패·수정을 기록한 뒤 영상 소재를 선정하라. 사용자 자료나 실행 권한이 없으면 적용 후보로 남기고 실제 사용한 것처럼 영상화하지 마라. 하루 3편 목표 때문에 불필요한 작업이나 허위 성과를 만들지 마라. 검증한 조사 글을 쇼츠의 기능→사용 단계→적용 사례→결과 확인으로 바꾸고 장문 분석은 칼럼형 후보로 보관하라. 이전 영상과 중복되지 않게 하라. 실제 실행과 설명용 예시를 구분하라.
고정 음성은 ElevenLabs Han Aim / eleven_v4이고 전환 효과음은 없다. 현재 호스트에서 해당 보이스와 모델을 사용할 연결이 실제 있는지 확인하라. 앱 연결이 CLI에도 자동 제공된다고 가정하지 마라. 다른 TTS로 대체하지 말고 한도·연결이 없으면 해당 단계를 대기시켜라. 추가 충전·구독·유료 재시도는 하지 마라.
가능한 경우 새 장면과 음성·자막으로 MP4를 생성해 프레임과 전체 디코딩·내용을 검수하라. 같은 샘플을 재출력해 새 영상 수를 채우지 마라. 제작 명세를 새 작업에 연결하고 검수한 작업만 승인하라. 채널 ID와 OAuth 및 uploads_enabled가 모두 검증된 경우에만 studio/youtube/publish.py로 미래 KST 09·14·20시 슬롯에 예약하라. 이 PC의 인증·연결이 없으면 게시하지 말고 대기열에 남겨라.
실제 생성 파일, 검수 결과, 실제 video_id와 예약 시간을 기록하라. 업로드 결과가 불확실하거나 이미 전송한 파일은 다시 보내지 마라. 비밀번호·인증 코드·토큰을 Git이나 대화에 남기지 마라. 완료한 단계와 막힌 단계를 구분해 보고하라.

신규 AI 영상은 --work-case로 실제 사례에 연결한다. content_mode=applied_work인 명세는 work_case_ref와 실행 증거가 필요하다. 모의 검사·부분 구현·실제 운영의 범위를 대본에서도 정확히 구분하라.

현재 사용자 우선순위는 video-channel 분야의 영상 제작·채널 운영 자동화다. game-development, app-development, agent-setup은 추후 확장 계획이며 실제 사용자 과제 없이 새 작업을 임의로 시작하지 마라. 분야마다 업무에 재사용할 코드·설정·템플릿과 공개용 사례를 함께 남겨라.
