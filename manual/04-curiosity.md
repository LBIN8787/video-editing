# 04. curiosity — 몰랐던 이유 (다양한 지식과 호기심)

**욕망:** 궁금증을 풀고 싶다. 핵심은 **평소엔 궁금하지 않았지만, 듣는 순간 궁금해지는 것**을 건드리는 것.
**약속:** "누구나 아는 그것의, 아무도 몰랐던 이유."
**범위 (2026-11-11 사용자 요청):** 역사·심리·과학만이 아니라 **AI·기술과 미래**도 포함 — "궁금하다" 그 자체가 기준입니다 (예: AI 는 왜 그럴듯하게 틀릴까, AI 는 꿈을 꿀까). 기술 주제도 같은 틀(익숙함·틈·답·반전·장면·연결)을 지키고, 업계 뉴스 정리는 ai 채널로 보냅니다.
**시청자:** 모든 일반인. 지식이 없어도 이야기를 따라올 수 있어야 한다.

## 0. 설명보다 호기심이 먼저 — 콜드 오픈 (v17, 2026-11-12 사용자 요청)
> "호기심·일상·잡다한 내용을 다루는 채널은 다짜고짜 설명에 들어가지 말고, 시청자가 듣고 싶게끔 먼저 호기심을 유발하고,
>  이를 바탕으로 대본을 쓰고, 이와 관련해 제목을 지어 달라."

**순서 (v23·v24, 2026-11-14 사용자: "인트로는 빼 주세요"): 첫 문장부터 훅(장면 하나 → 질문) → 이야기.** 시청자에게 말 걸기("~하실 분?")로 여는 것도 하지 않음 (README §2-3). 인사·채널 이름·채널 약속·순서 예고를 넣지 않습니다.
(이전 v18 '짧은 인사 → 소개 → 훅'은 폐지. 시청자는 홈 피드에서 우연히 들어온 사람이라 채널 소개를 기다려 주지 않습니다 — docs/29.)

### 0-1. 훅을 먼저 정한다 (대본보다 먼저, `topic_brief.json` 의 `hook`)
```json
"hook": {"type": "장면", "line": "2023년 뉴욕의 한 법정. 변호사가 낸 판례 여섯 개가 전부 세상에 없는 판례였습니다.",
         "gap": "AI는 왜 없는 걸 그렇게 자신 있게 지어냈을까?", "withheld": "답(시험 채점 방식)은 3장에서",
         "payoff_scene": 9}
```
| 훅 종류 (`type`) | 이렇게 시작 | 예 |
|---|---|---|
| **장면** | 사람·장소·날짜가 있는 한 순간 → 이상한 점 | "1918년 3월, 미국 캔자스의 군 취사병이 열이 났습니다. 그런데 이 병의 이름은 '스페인' 독감입니다." |
| **모순** | 누구나 아는 것 + 맞지 않는 사실 하나 | "스페인 독감은 스페인에서 시작되지 않았습니다." |
| **상식 깨기** | 시청자가 믿는 것을 먼저 말하게 하고 뒤집을 예고 | "AI가 틀리는 건 거짓말을 배워서라고 생각하시죠? 사실은 정반대입니다." |
| **숫자 충격** | 사람이 느낄 수 있는 크기의 숫자 하나 | "하루 만에 시가총액 130조 원이 늘었습니다. 회사가 한 일은 단 하나였습니다." |
| **나와의 연결** | 시청자가 오늘 겪은 일에서 출발 | "엘리베이터 닫힘 버튼, 눌러도 안 닫히는 것 같지 않으세요?" |

**훅의 규칙**
- 15~40초, 박자 2~4개. **답은 말하지 않습니다** (`withheld` — 답이 나오는 장면을 정해 두고 그때 회수, `payoff_scene`).
- 마지막 박자는 **질문 하나**(`gap`)로 끝나야 합니다. 그 질문이 영상 전체의 질문(`viewer_question`)입니다.
- 설명 낱말(원리·정의·배경 설명, "~란 ~입니다")로 시작하지 않습니다. 사실 하나 + 이상한 점.
- 과장 금지: 놀라움은 장면과 숫자가 만듭니다. 훅의 사실도 팩트시트로 확인한 것만.

### 0-2. 대본은 훅에 매달린다
- 첫 장면은 곧바로 **훅** (`hook.line` → `hook.gap` 질문). 인사·채널 소개·순서 예고 없음 (v23). 채널 이름은 썸네일·화면 구석 표시로 충분.
- 연결이 자연스럽게: 소개 → 훅은 "그런데 말이죠", "이런 일이 있었습니다"처럼 이야기로 넘어갑니다. 소개 문장에서 답을 미리 말하지 않습니다.
- 장마다 훅의 질문에 한 걸음씩 다가가고, 장 표지 멘트는 **남은 궁금증**으로 잇습니다 ("그런데 이상한 점이 하나 더 있습니다").
- 답은 영상의 2/3 지점 이후에, 그리고 **마지막 문장은 훅의 질문에 대한 답 한 줄**.

### 0-3. 제목은 훅에서 나온다
- 제목 = 훅의 **틈(gap)**을 그대로 쓰되 답은 숨김. 훅에 없는 약속을 제목에 넣지 않습니다(낚시 금지).
- 3개 후보(`title_options`)는 훅 종류를 바꿔서: ① 질문형(gap 그대로) ② 장면·숫자형(훅의 장면·숫자) ③ 상식 깨기형("~인 줄 알았는데").
- 썸네일 글자는 제목을 반복하지 않고 훅의 장면·감정을 보탭니다. `title_why` 에 "훅의 어느 부분에서 왔는지"를 적습니다.
- 예 (AI 환각): 훅 "없는 판례 여섯 개" → ① "AI는 왜 그럴듯한 거짓말을 할까?" ② "없는 판례 6개를 만든 AI, 범인은 따로 있었다" ③ "AI가 거짓말을 배운 줄 알았는데"

`check` (curiosity, 롱폼): `hook` 있음 · 첫 박자부터 곧바로 훅(첫 두 장면 안, 순서 예고·설명보다 앞) · 훅의 질문(gap)이 나옴 (MUST), 제목과 훅이 같은 낱말을 나눔 (SHOULD).

### 0-4. 이야기를 들려주듯 — 정보형(주식)과 다른 양식 (v21, 2026-11-13 사용자 요청)
> "호기심 채널은 주로 이야기를 들려주는 방식이기에 이 대본에 맞추어 애니메이션 효과를 넣어 주세요.
>  주식 채널은 정보를 제공한다 느낌이 있기 때문에 서로 양식이 조금 다를 수밖에 없다." (참고: 미주일기 XE-9raLLQTQ)

| | 주식(market) — 정보 제공 | 호기심(curiosity) — 이야기 |
|---|---|---|
| 대본 | 숫자 → 이유 → 오늘 볼 것 (보도·설명) | **장면 → 인물 → 사건 → 이상한 점 → 반전 → 답** |
| 화면 뼈대 | 요약판 + 말에 맞춰 생기는 사물 (`motion`, 09 §5) | **이야기 그림판** (`story`, styles/story-board): 큰 종이 한 장에 사람·사물이 선으로 그려지고 카메라가 따라감 |
| 숨 쉬는 장면 | 뉴스 카드·막대·체크리스트 | 질문·결론 한 줄(kinetic) · 인용(quote) · 숫자 대비(versus) |
| 썸네일 | 사진 + 큰 글씨 | 종이 + 같은 선 그림 + 큰 글씨 (`layout: board`) |

**이야기 대본 쓰는 법**
1. 문장마다 **때·곳·사람·사물** 중 하나를 넣는다 → 그 낱말이 화면의 그림이 된다 ("1997년 5월 11일, 미국 뉴욕. 카스파로프가 체스판 앞에…").
2. 설명은 이야기 속 인물의 입으로 ("모라벡은 1988년 책에 이렇게 썼습니다"), 정의 문장("~란 ~이다")은 쓰지 않는다.
3. 장면 하나 = 이야기 한 토막(3~6박자), 끝 박자는 지금까지 그린 것을 한 화면에 모아(카메라 `full`) 대비·질문으로.
4. 처음에 나온 사물(체스·티셔츠)을 끝까지 다시 불러 **이어지는 이야기**로. 마지막 장면은 첫 장면의 그림으로 돌아온다.
5. 말투는 들려주듯: "~였습니다 / ~였죠 / ~거든요 / ~까요?". 보도문 말투(~것으로 알려졌다)는 한두 번만.
6. `story-board` 는 뼈대 스타일 — 한 스타일 상한 40% 대신 **85%** (`check` 가 레시피의 `backbone` 으로 판단). 같은 type 3연속 금지는 그대로.
7. **재료 (v2, docs/26):** 사람은 실제 사진(CC0·CC BY·PD) 또는 이름 카드 — 막대 인물 금지. 증거는 기사·논문 캡처 + 말할 때 형광펜. 아이콘은 스티커. 한 장면에 같은 재료 50% 이하, 배경(밝은 종이·어두운 종이·사진 전체)을 장면마다 바꾼다.
8. 직접 그린 그림만 쓴 영상은 자료 화면 출처 검사(G2) 대신 그림판으로 통과 — 사진·영상을 쓰면 출처 규칙 그대로.

> **채널 해석 (사용자, 2026-11-14):** 주식·AI·이슈는 시청자가 자기 의지로 와서 정보를 원한다(정보 + 재미 곁들임). 호기심은 **정보 전달이 목적이 아니라** 이야기를 들려주는 채널이다 → 정보 카드·요약판·글자 쪽지 대신 이야기를 연기하는 애니메이션 (manual/README §1-1).

### 0-5. 의도 먼저 — 애니메이션 무대 (v22, 2026-11-14 사용자 기각 반영)
> "중간중간 너무 난잡하다. 제작에 앞서 무엇을 목표로 만드는지, 시청자의 욕망을 어떻게 채울지 먼저 정의하고 매뉴얼을 작성하라.
>  대본 내용을 소제목처럼 글로 쓰거나 사진을 무작정 붙이지 말고, 대본을 바탕으로 애니메이션을 넣어라. 의도를 명확히."

**기각 원인 (v21·v3):** ① 한 장의 큰 종이에 사진·문서·쪽지·도장·그림을 계속 쌓아 화면이 콜라주가 됨 ② 대본을 글자 쪽지로 다시 씀(자막과 중복) ③ 그림이 '나타나기'만 하고 대본의 행동을 하지 않음 ④ 무엇을 위해 그 그림을 넣었는지 적은 곳이 없음.

#### A. 만들기 전에 정한다 (`02_script/intent.md`, 없으면 렌더하지 않음)
1. **제작 목표 한 줄** — 영상이 끝났을 때 시청자 머리에 남을 것. 예: "체스보다 빨래가 기계에게 어렵다 — 그리고 내 손이 생각보다 대단하다."
2. **욕망 → 영상이 채울 것** — 채널 욕망(궁금증을 풀고 싶다)을 이 영상에서 네 단계로:
   | 단계 | 시청자의 마음 | 영상이 할 일 | 화면의 수단 |
   |---|---|---|---|
   | 끌림 | "어? 이상한데" | 두 사실이 부딪치는 순간을 보여 줌 | 두 주인공의 대결 (예: 체스 말 vs 티셔츠) |
   | 따라감 | "그래서?" | 한 번에 한 생각, 주인공이 이야기를 연기 | 무대 위 주인공 1명 + 행동 |
   | 깨달음 | "아, 그래서구나" | 답을 말이 아니라 그림의 움직임으로 | 은유 장치 하나 (시소·긴 길과 한 점 등) |
   | 연결 | "내 이야기네" | 처음의 그림으로 돌아와 시청자의 삶으로 | 처음 주인공 재등장 + 시청자의 손·집 |
3. **기억할 한 장면** — 썸네일이 되고, 처음·가운데·끝에 다시 나오는 그림 (모티프).

#### B. 장면마다·박자마다 의도표 (`02_script/hybrid.json` 의 `stage` 장면)
- 장면: `goal` = "이 장면이 끝나면 시청자는 ___ 를 안다/느낀다" 한 줄.
- 박자: `why` = 이 박자의 그림·움직임이 시청자에게 주는 것 (예: "기권 = 왕이 쓰러짐 — 졌다는 걸 말보다 먼저 보여 줌"). **why 가 없는 박자는 검사 실패.**
- 대본의 **동사가 움직임이 된다**: 앉다·일어나다·문을 닫다·집어 들다·미끄러지다·걷다·쓰러지다 → 그림이 그 동작을 한다. 동사가 없는 박자는 카메라·모티프로 잇고 why 에 이유를 적는다.

#### C. 화면 규칙 (무대 `stage`, `ytflow/stages/stage.py`)
| 규칙 | 이유 |
|---|---|
| **한 화면 = 한 생각**: 주인공 1 + 소품 ≤ 2, 동시에 보이는 것 ≤ 4 (검사: `stage/crowded`) | 난잡함의 원인은 '쌓기'. 다음 박자에 필요 없는 것은 퇴장시킨다 |
| **화면 글자는 하나만**, 자막이 말하는 문장을 다시 쓰지 않음 — 연도·숫자·이름·핵심어만 (검사: `stage/text`) | 자막과 같은 글은 읽을 거리만 늘림. 쪽지·소제목·말풍선 질문 나열 금지 |
| **사진·문서는 증거 순간에만**: 한 장면에 하나, 가운데 크게, 말이 끝나면 퇴장 | 실존 인물·기사·논문은 사실이라 그대로 보여 주되, 장식으로 쌓지 않음 |
| **나타나기보다 연기**: 들어오기·나가기·걷기·쓰러지기·움츠리기·모양 바뀌기·미끄러지기·기울기 | 그림이 대본의 사건을 직접 하면 설명 없이 이해됨 |
| **은유 장치 하나로 답을 보여 줌** (시소·길·저울 등), 장면마다 장치를 바꾸지 않음 | 깨달음은 한 그림이 움직이는 순간에 옴 |
| 카메라는 고정이 기본, 움직일 때는 **시간·공간 이동**(진화의 긴 길을 따라감)일 때만 | 의미 없는 줌은 어지러움 |
| 같은 그림체(모델 시트, `art-gen`)로 주인공을 만들고 처음·중간·끝에 다시 씀 | 모티프가 이야기를 묶음 |

#### D. 검사 (`layout_qa.json`, 렌더 때 자동)
`stage/no_goal` 장면 goal 없음 · `stage/no_why` 박자 why 없음 · `stage/crowded` 동시에 5개 이상 · `stage/text` 글자 2개 이상 동시 · `stage/static` 움직임 없는 박자가 30% 넘음. 모두 비어야 사람 검토로 보냄.

### 0-6. 시청자 먼저 — 상권 조사 → 대본 → 편집 (v23, 2026-11-14 사용자 기각 반영)
> "가장 근본적으로 대본 구성부터 문제다. 주 고객층·시청자층과 유입 경로·유입 이유를 상권 조사처럼 알고, 니즈에 맞춰 대본을 짜고,
>  대본을 바탕으로 편집해야 한다. 대본 자체가 설명·서술·지식 욱여넣기 — 지식 습득 쪽으로 치우쳐 있다."

**순서 (바꾸지 않음):** ① 시청자 조사 → ② 대본 → ③ **대본만 사용자 검토** → ④ 편집 의도(§0-5) → ⑤ 렌더. 편집으로 대본의 문제를 덮을 수 없다.

#### ① 시청자 조사 (`01_research/audience.md`, 채널 공통 근거는 `docs/29-curiosity-audience.md`)
| 항목 | 이 채널에서 알아낸 것 (docs/29) |
|---|---|
| 주 시청자 | 원래 그 주제에 관심 없던 일반인. 밥 먹으며·쉬면서 긴 영상을 '밥친구'로 트는 사람 |
| 유입 경로 | **홈 피드·추천** (검색 아님) — "평소엔 관심 없다가 제목 보고 궁금해져서 들어온 사람" |
| 유입 이유 | 제목 한 줄의 모순·가정이 **내 몸·일상**을 건드림 ("뚱뚱한 사람이 굶어 죽으면 뚱뚱한 채로 죽을까?") |
| 끝까지 보는 이유 | 공부가 아니라 **재미·몰입** ("10분이 1분처럼", "영화 한 편") — 사람(주인공), 감정, 웃음, 나와 연결 |
| 다시 보는 곳 | 결론·감정이 터지는 곳 (영상의 70~90%) |
`audience.md` 에는 이 영상의 주 시청자·유입 경로·유입 이유·끝까지 보는 이유·다시 볼 곳·하지 않을 것·제목 후보를 쓴다 (`check` G1 MUST).

#### ② 대본 규칙
1. **주인공 한 명을 따라간다** (사람·로봇·동물). 장면마다 주인공이 바뀌는 '사례 모음'은 강의가 된다.
2. **형식·진행·말투는 README §2-3 (미주일기 문법)**: 때·곳·사람이 있는 여는 장면 → 질문 하나 → 한 줄기 이야기를 시간 순서로 → 처음 장면으로 돌아와 닫기. 시청자에게 말 걸기("~하실 분?", "손을 펴 보세요")로 열지 않는다 (v24 에서 바뀜).
3. **감정은 디테일에서**: 사람의 사연·뜻밖의 일화·숫자의 대비가 놀라움과 여운을 만든다. 말투로 흥분을 만들지 않는다 (억텐 금지).
4. **지식·설명·수치 문장 ≤ 30%** (MUST). 대본 문장 앞에 ●이야기·행동·감정·말 걸기 / ○지식·설명·수치를 사람이 표시해 `02_script/script_vN.md` 로 저장 → `check` 가 센다.
5. 연도·기관·인명은 이야기에 꼭 필요할 때만, 하나씩. 출처는 말로 읽지 않고 화면 아래·설명란으로. 인용문 낭독 장면·목차("첫째·둘째") 쓰지 않음.
6. 숫자는 **대비가 되는 것 하나**만 ("3초" vs "600억 원", "수백만 년" vs "1,400년").
7. 결론은 **85% 지점의 한 문장** — 시청자가 다시 돌려 볼 문장.

#### ③ 대본 검토 게이트
