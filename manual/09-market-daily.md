## 0. 한 줄 정의
전날 시장(미국·한국)을 **움직인 것**을 1차 출처로 확인하고, 그것이 **무엇으로 이어지고 무슨 뜻인지**까지 깊게 설명한다 — 10분 안팎이 기본, 주제가 깊으면 더 길게 (v24 최소 10분은 깊이의 최소선, 맞출 숫자가 아님 — README §2-4). 투자 권유는 하지 않는다.

| 하는 것 | 하지 않는 것 |
|---|---|
| 움직인 이유를 원인 종류(이슈·보고서·전망·실적)로 나눠 설명 | 사라·팔라·목표가 단정 |
| 공시·실적 자료·발언 **원문**을 보여 주기 | 출처 없는 '카더라', 찌라시 단정 |
| 사실과 해석을 나눠 말하기 ("여기서부터는 해석입니다") | 장중 값을 마감처럼 말하기 |
| 오늘 확인할 것(날짜·시각)으로 끝내기 | 하루 움직임으로 장기 결론 |

## 2. 브리핑이냐 심층이냐 (요일 고정 아님)
daily_brief 의 이야기마다 `depth`(브리핑 / 심층 후보)와 이유가 적힙니다. **최종 판단은 사람**. 아래 신호 **둘 이상**이면 심층:
1. 원인이 여러 갈래로 얽힘 · 2. 한 사건이 시장 전체를 움직임 · 3. 어닝콜·연준·정부 발표의 긴 설명이 핵심 · 4. 며칠째 이어지는 이야기의 전환점 · 5. 한국 시장으로 이어지는 고리가 김

| | 브리핑 (10분 안팎~) | 심층 (12분~, 자료가 많으면 20분도) |
|---|---|---|
| 구성 | 시장 한 장 → 이야기 2~3개 → 한국 → 오늘 볼 것 | 앞 1분 시장 요약 → 한 주제를 4~5장으로 |
| 어닝콜이면 | 한 장(章)으로 요약 | `03 §0-1` 어닝콜 해부 (숫자·약속 → 경영진의 말 원문+번역 → 의미 → 남은 숙제 → 확인할 약속) |
| 하루 편수 | 기본 1편, 할 이야기가 많으면 더 (§2-1) | 그날 브리핑을 대신하거나, 브리핑과 따로 한 편 더 |

### 2-1. 하루 여러 편 — 상한 없음 (v39, 2026-11-17 사용자)
> "반드시 하루1편을 올리는 것이 아니라 각 소스영상 인터뷰영상 주제 등 할 이야기가 많다면 하루에 세개까지 영상을 올려도 됩니다 즉 제한을 두지는 않는다는거에요"

- **아침 브리핑 1편은 기본**이고, 아래 중 하나라도 있으면 **같은 날 따로 한 편 더** 만든다. 편수에 상한은 없다(세 편이 보통의 위쪽 — 넘으면 정말 따로 다룰 만한지 한 번 더 본다).
  1. **원본 영상이 강할 때** — 경영진·당국자·이름난 투자자의 인터뷰·기자회견·어닝콜이 그 자체로 할 이야기가 많음 (`bite` 중심 해설, §3-5)
  2. **어닝콜·큰 실적** — 브리핑의 한 장으로 줄이기엔 숫자·약속·질문이 많음 (03 §0-1 어닝콜 해부)
  3. **브리핑과 다른 줄기의 큰 사건** — 브리핑 중심축과 이어지지 않는 두 번째 사건
  4. **리서치·인사이트가 두꺼울 때** — SemiAnalysis 같은 보고서·여러 사람의 엇갈린 시각을 제대로 맞대려면 한 편이 필요함 (§3-4·§3-4-1)
- **나누는 법:** 브리핑은 그날 시장 전체 + 중심 사건을 짧게, 따로 만든 편은 한 주제를 깊게. 브리핑 안에서 "이 이야기는 따로 한 편으로 자세히 다뤘습니다"로 잇는다(같은 장면·문장을 두 편에 반복하지 않음 — 유튜브 반복·재사용 콘텐츠 정책, §13).
- **이름:** 브리핑 `<YYYYMMDD>-market-daily` · 더 만드는 편 `<YYYYMMDD>-market-deep-<주제>` (어닝콜은 `-market-call-<티커>`) → 재생목록 '심층 분석'. 편마다 프로젝트·팩트시트·검사(`check`)·썸네일 A/B/C 를 따로 갖고, 같은 프로젝트를 두 번 올리지 않는다.
- **공개 시각:** 같은 날 두 번째·세 번째 영상은 `yt-publish` 가 자동으로 12:00·18:00 에 예약 (`channel.yaml` `youtube.publish_slots`, 넘으면 2시간씩 뒤). 시각을 정하려면 `--at`.
- **우선순위:** 시간·사용량이 모자라면 정확한 브리핑 1편이 먼저. 더 만드는 편은 브리핑을 올린 뒤에 시작한다.
- **보고:** 그날 올린 편마다 주소·제목·길이를 함께 알린다.
- **확인 필요 (2026-11-17):** `manual/11-workflow.md`(v38)는 "최종 승인은 사용자만, 에이전트는 업로드·공개하지 않음"인데, 매일 시장 루틴은 06:05 자동 제작 → 08:00 예약 공개를 해 왔다. 매일 시장 채널에 어느 쪽을 적용할지 사용자 결정 전까지는, 더 만드는 편(두 번째 이후)은 **올리지 않고 완성본·포장을 보고해 승인을 받은 뒤** 올린다.

**운영 원칙 (v30, 2026-11-15 사용자: "시장이 열리는 날에는 그날의 시장 브리핑과 시장을 흔든 이슈들을 정리하고 관련 인사이트나 매체·인물들의 인사이트 등을 분석·조사하고 보고합니다. 장이 열리지 않는 날에는 종합적으로 한 주의 이슈들과 인사이트들을 점검할 수 있도록 운영합니다")**

| 날 | 무엇을 | 프로젝트 이름 |
|---|---|---|
| **장이 열린 다음 날 아침** (화~토 아침 = 전날 미국·한국 장, 월 아침 = 금요일 미국 장 + 주말 소식) | 그날의 시장 브리핑 + **시장을 흔든 이슈** 정리 + 그 이슈에 대한 매체·인물(경영진·당국자·애널리스트·투자자)의 인사이트를 조사·분석해 보고 (03 §0-3 사건 중심축, 입장별 해석) | `<YYYYMMDD>-market-daily` (복잡하면 심층) |
| **장이 열리지 않는 날** (토·일·휴장일) | **한 주 종합 점검**: 그 주의 이슈들을 다시 묶고, 그동안 나온 인사이트·매체 해석이 그 뒤 숫자로 맞았는지·바뀌었는지 점검 + 다음 주 일정·실적 (§2 아래 '다음 주 볼 것') | 토 `<YYYYMMDD>-market-weekly` (한 주 이슈 종합) · 일 `<YYYYMMDD>-market-review` (한 주 인사이트 점검: 누가 무엇을 말했고 그 뒤 어떻게 됐나 + 다음 주 일정·실적 상세) |
- 산업·테마 하나만 다루는 '일요일 분석글'은 기본에서 뺍니다 (그 주 이슈와 이어질 때만 점검 회차 안의 한 장으로).

**매주 '다음 주 일정·실적' 브리핑과 분석 (2026-11-15 사용자: "앞으로의 시장에서 주목해야 할 일정들이나 실적발표 등은 무엇이 있는지 등도 매주 브리핑하고 분석·설명할 수 있도록")**
- 주간 분석(토)에는 **'다음 주 볼 것' 장(章)** 을 따로 둡니다 — 마지막 체크리스트 한 장이 아니라 2~4장면, 2~4분.
- 무엇을: ① 경제 지표·중앙은행 (미국 CPI·PPI·고용·PCE·GDP, FOMC·의사록·연준 인사 연설, 한국은행 금통위·수출입) ② **실적 발표** (시장을 움직일 대형·AI·반도체·한국 대표 기업) ③ 정책·이벤트 (선거·규제·만기·공시 예정) — 모두 **한국 시간**과 함께.
- 어떻게: 일정마다 "왜 중요한가 → 지난번 숫자·회사 가이던스(전망) → 무엇을 보면 되나(볼 숫자 1~2개) → 결과가 위/아래면 무엇으로 이어지나(해석) → 한국 시장 연결". 시장 컨센서스 숫자는 매체마다 다르면 쓰지 않고 회사가 낸 가이던스를 기준으로.
- 출처: 회사 IR 일정·8-K 보도자료(실적일), BLS·BEA·연준·한국은행·관세청 공식 일정표, DART. 일정표 사이트 한 곳만 보고 쓰지 않음.
- 팩트시트에 `## 다음 주 일정` 표: `| 날짜(한국 시간) | 무엇 | 종류(지표·실적·정책) | 지난번·가이던스 | 볼 것 | 출처 |` — 5줄 이상, 실적 1줄 이상. `check` (주간 MUST).
- 매일 브리핑도 마지막 '오늘 볼 것'에 그날·그 주의 실적·지표를 날짜·시각과 함께.

**심층·주간·분석글은 `03 §0-2` (v26)**: 알려진 사실(`known`)이 아니라 자료를 엮어야 보이는 것(`new_angle`)으로 제목·훅을 만들고, 팩트시트에 `## 자료 지도`(보고서·발언·행동을 날짜 순으로, 각 자료의 의미)와 `## 매체 프레임`(국내·해외 매체가 어떻게 다뤘나)을 먼저 채운 뒤 대본을 씁니다. 말과 행동이 어긋나는 곳이 가장 강한 단서입니다.

## 3. 조사 — 원인은 1차 출처로
### 3-0. SAVE(오선) 소식은 기본으로 확인 (2026-11-14 사용자 요청)
> "주식에 관해서 추가로 소스 확보를 할 때 오선의 SAVE 를 활용하여 여기 소식은 기본적으로 확인하도록 하세요."

- **무엇:** SAVE — '투자의 모든 소식, 이제 한 곳에서' (Fivelines, 앱 + 웹 https://www.saveticker.com). 글로벌 속보·기업 리포트·경제 지표·투자 일정을 요약해 보여 줌.
- **어떻게:** 사람이 앱/웹에서 본다. 웹은 Cloudflare 봇 확인이 걸려 있고 robots.txt 가 AI 수집기를 막으며(`ai-train=no, use=reference`), 그래서 **자동 수집·우회·비공개 API 호출은 하지 않는다.**
  - `python -m ytflow daily` 가 `01_research/save_check.md` (속보·리포트·경제지표·일정 표)를 만든다 → 본 것을 내 말로 한 줄씩, 상태 `확인함`.
  - **메모 없이 (지금 도는 길, docs/28 §1 — 2026-11-14 완료):** 휴대폰 SAVE 알림 → **MacroDroid** 가 본인 Gmail 로 `[save알림]` 메일 → **30분마다 도는 감시**(Pickle 정기 작업, 스팸함 포함)가 `inbox/save/<YYYYMMDD>.md` 에 `- <내용> (알림 MM-dd HH:mm)` 로 자동 커밋(한국 06:00 이후 알림은 다음 날 파일) → daily 가 표에 옮김. `tools/save-forward`(Apps Script)는 **켜지 않음** — 백업용이고, 같이 켜면 같은 알림이 두 줄로 쌓인다.
  - 손 메모도 그대로 됨: 전날 밤~05:50 사이 `inbox/save/<YYYYMMDD>.md` 에 올리면 daily 가 표에 옮긴다. 메모도 없으면 상태를 `확인 못 함: 이유` 로 적고 보고에 남긴다 (빈칸이면 `check` MUST 실패).
- **쓰는 법:** SAVE 소식은 **단서**. 이야기 고르기(§2)의 후보에 더하고, 영상에 넣는 것은 아래 §3-1 의 1차 출처로 다시 확인해 factsheet 에 쓴다. SAVE 요약 문장을 대본에 그대로 옮기지 않는다.
- daily_brief(시세·뉴스 검색)에 없던 소식이 SAVE 에만 있으면 그 이유(시간대·출처)를 확인한 뒤 넣을지 정한다.

### 3-0-1. 뉴스레터 화제도 같은 '단서' 자리 (2026-11-16 사용자 승인, docs/36)
> 2026-11-15 사용자: 무료 뉴스레터 구독(소스 탐색·참조용) → "진행해주세요". 2026-11-16 매뉴얼 반영 "네".

- **무엇:** 구독한 무료 뉴스레터(Axios·Daily Upside·어피티 등, 목록 `config/newsletters.yaml`)를 매일 자동으로 모은 `inbox/newsletters/<YYYYMMDD>.md` — 채널별로 소재(원래 제목)·링크·분류만 있음.
- **어떻게:** `daily_brief.md` 끝 **⑦ 뉴스레터 화제**를 SAVE 와 함께 훑고, 이야기 고르기(§2) 후보에 더한다. 수집이 비었으면 그냥 넘어간다(SAVE 와 달리 MUST 아님).
- **쓰는 법:** SAVE 와 같다 — **단서**일 뿐, 뉴스레터 문장을 대본·화면에 옮기지 않고, 숫자·발언은 §3-1 의 1차 출처로 다시 확인한다. 미국 아침 판은 한국 전날 밤에 오므로 브리핑 원인보다 심층·주간 배경에 맞다(docs/36 §1).
- **다른 채널:** 호기심·AI 채널은 주간 소재 고르기에 `python -m ytflow newsletters show --brand <b> --days 7`. 공공 자료 그림은 `python -m ytflow archive si "검색어"`(스미스소니언 CC0)도 쓸 수 있다.

### 3-1. 원인 종류별 어디서 확인하나
| 원인 종류 | 1차 출처 (먼저) | 보조 (보도) | 대본 표현 |
|---|---|---|---|
| **이슈** (사건·인사·규제·계약) | 회사 공시 (미국 SEC 8-K, 한국 DART), 보도자료, 당국 발표 | 통신사·주요 경제지 2곳 이상 | "회사는 공시에서 ~라고 밝혔습니다" |
| **실적** | 실적 보도자료·IR 자료, 10-Q | 실적 요약 기사 | 예상 vs 실제 vs 1년 전 |
| **전망** (가이던스·연준·지표) | 어닝콜 공식 녹취록(`earnings-call`), 연준 성명, 통계 원문 | | 원문 문장 + 번역 |
| **보고서** (증권사·기관) | 보고서 공개분 | 인용 보도(매체·날짜) | "○○는 ~로 봤습니다 — 한 기관의 의견" (목표가는 권유처럼 들리면 빼기) |

- SEC 공시: `https://www.sec.gov/cgi-bin/browse-edgar?action=getcompany&CIK=<티커>&type=8-K` (curl 은 `-L` 로 넘겨받기). 한국: DART.
- 어닝콜: 회사 IR 의 **공식 녹취록** → `python -m ytflow earnings-call <프로젝트> <PDF·주소> --ticker <티커> --period <분기>`
- 막힌 곳(403·봇 확인)은 **우회하지 않음** — 다른 1차 출처나 보도 2곳 일치로.

### 3-2. 팩트시트 쓰는 법 (`01_research/factsheet.md`)
- 번호 + 확인 표시: ✅ 1차 출처·시세로 확인 / ⚠️ 보도(1곳 또는 회사 확인 없음) / 💬 해석
- 모든 줄에 **출처 주소** (yt-pack 이 설명란 출처로 그대로 가져감)
- `## 해석` 칸 (check MUST): 해석마다 근거 번호
- `## 쓰지 않는 것`: 매체마다 다른 숫자, 1곳뿐인 주장, 사적 인물, 목표가

### 3-3. 데이터 함정 (실제로 겪은 것)
| 함정 | 막는 법 |
|---|---|
| 장중 값을 마감으로 씀 | `daily` 는 시장마다 **장이 끝난** 날만 씀. 대본에 날짜를 붙임 ("12일 마감") |
| 야후 지수·환율·원자재 갱신 늦음 (예: 11/13 아침 코스피가 11일 값) | daily_brief 의 ⚠️ 표시 확인 → 거래소·마감 기사로 대체, 팩트시트에 적기 |

### 3-4. 사람·매체의 인사이트 — 사실과 나눠서, 넉넉하게 (v36, 2026-11-17 사용자 요청)
> "내가 이전에도 말했지만 다른 사람들이나 유명인들 매체 등등 여러 인사이트들을 그런 내용이 좀 부실한거같아 물론 사실과 인사이트는 별개로 구분해야하고"

지금까지는 `## 매체 프레임`(제목 한 줄씩)과 증권사 코멘트 한두 줄이 전부였습니다. 이제 **사람이 무엇을 근거로 어떻게 봤는지**를 따로 모으고, 영상에 장(章)으로 넣습니다.
- **세 가지를 섞지 않는다 (표시도 셋):** ✅ 사실(공시·시세·통계) · 💭 **인사이트**(이름 있는 사람·매체의 시각 — 맞을 수도 틀릴 수도 있음) · 💬 이 채널의 해석.
- **누구의 말을 모으나:** 당국자(재무장관·연준·상무부·한국은행) · 경영진(CEO·CFO) · 이름난 투자자·펀드매니저 · 애널리스트·이코노미스트(증권사·은행·연구소) · 언론인·칼럼니스트·매체 사설 — **공인과 직함이 있는 사람만**. 사인(私人)·익명 커뮤니티 글은 쓰지 않음.
- **어디서:** 방송 인터뷰(CNBC·블룸버그·폭스 비즈니스·야후 파이낸스, 국내 경제 방송) · 공식 녹취록·기자회견 · 칼럼·사설·보고서 공개분 · 본인 X 계정(공식 임베드 캡처) · 팟캐스트. SAVE·뉴스레터에 뜬 발언도 **원문(방송·기사·게시물)** 을 찾아 확인한 뒤 씀.
- **팩트시트 `## 인사이트` 표 (check MUST, 시장 채널):** `| 누가 (이름·직함·소속) | 어디서 (매체·방송·자리) | 국내·해외 | 날짜 | 원문 한 줄 | 입장 (낙관·우려·중립) | 근거로 든 것 | 출처 주소 |` — **4줄 이상, 입장 2가지 이상, 국내·해외 각 1명 이상.** 원문은 따옴표 그대로(영어면 영어로), 번역은 대본에서.
- `check` 는 11/18 회차부터 검사합니다.
- **대본 (check MUST):** 인사이트 장면 **2개 이상** — 장면에 `"insight": true`. 브리핑은 한 장(2~3명), 심층·주간은 3~5명. 형식은 `quote`(원문+번역) · `bite`(그 사람의 목소리, §3-5) · `versus`(엇갈린 두 시각).
  - 말로도 나눈다: "○○는 이렇게 봤습니다 — 사실이 아니라 한 사람의 시각입니다", "반대로 △△는 …". 화면에는 '의견' 표시가 자동으로 붙음.
  - **들려주고 끝내지 않는다:** 인사이트마다 이 채널이 가진 사실(시세·공시)과 맞대기 — "이 시각을 받치는 숫자는 …, 어긋나는 숫자는 …". 엇갈린 시각이 있으면 둘 다.
  - 시간이 지나 맞았는지 틀렸는지는 일요일 점검 회차(`-review`)에서 다시 봄.

#### 3-4-1. 업계 리서치는 기본으로 확인 — SemiAnalysis 등 (v37, 2026-11-17 사용자 요청)
> "그리고 이번에 세미 아날리스의 보고서에 대한 내용이 없는거도 아쉬워요"

- **AI·반도체·데이터센터 이야기면 매 회 확인:** SemiAnalysis(뉴스레터·주간 팟캐스트 — RSS 자동 수집, daily_brief ⑦) · 트렌드포스·카운터포인트 같은 업계 조사 기관 · 증권사 보고서 공개분. 그 주(최근 10일) 안의 글 가운데 오늘 사건과 이어지는 것을 `## 인사이트` 에 1줄 이상.
- **유료 보고서:** 회사가 공개한 부분(무료 미리보기·요약·팟캐스트 설명·대표의 공개 발언)만 쓴다. 로그인·결제벽을 넘지 않는다. 짧게 인용하고 "○○의 추정·의견"으로 — 그들의 숫자는 ✅ 가 아니라 💭(추정치)다.
- **제3자 요약 글**(다른 뉴스레터·블로그가 유료 보고서를 정리한 것)은 ⚠️ — 숫자는 원문 공개분에서 확인될 때만 쓴다.
- **맞대기:** 리서치의 예측·주장을 그 뒤 실제 일(공시·규칙·실적)과 맞춘다 (예: 11/12 "원격 접근 규제가 진행될 것" → 11/16 상무부 규칙). 리서치가 정책에 반대하면 그 반대 논리도 함께 보여 준다.
- **이어지는 사건이면** 이전 회차에서 찾아 둔 메모 `inbox/research/<날짜>-*.md` 를 먼저 읽는다.

### 3-5. 매체·인물의 인터뷰·방송을 영상 소스로 (v36, 2026-11-17 사용자 요청)
> "앞으로 영상에도 이런 매체나 언론인 언론사들의 인터뷰 내용이나 방송내용 등을 영상소스로 첨부했으면 좋겠어"

- **매 회 찾는다:** §3-4 인사이트 가운데 **영상이 있는 발언**을 찾아 팩트시트 `## 영상 소스` 표에 적는다 (check MUST — 못 찾으면 `없음: 이유` 한 줄).
  `| 누가 | 채널 (공식) | 영상 제목 | 날짜 | 주소 | 쓸 문장 (원문) | 권리 | 상태 |` — 상태: `받음` / `PC 필요` / `카드로 대체`.
- **고르는 순서:** ① 본인·기관 공식 영상(연준·백악관·의회·재무부 = 미국 정부 저작물 · 회사 IR 웹캐스트·공식 채널) ② **방송사 공식 채널**의 인터뷰·방송(CNBC Television·Bloomberg Television·Fox Business·Yahoo Finance, 국내 경제 방송 공식 채널). 다른 해설 유튜버의 영상은 쓰지 않음.
- **어떻게 쓰나 — 인용의 범위 (저작권법 제28조 '보도·비평을 위한 정당한 범위의 인용', 제35조의5 공정이용):**
  - 한 장면 **20초 이내**, 한 편 합계 **60초 안팎**까지. 그 사람의 핵심 문장만 (`bite` 장면, `python -m ytflow cut`) — 방송 한 꼭지를 통째로 틀지 않음.
  - 반드시 **앞뒤로 해설**(누가·언제·어디서 → 원본 → "이 말의 뜻은…" + 사실과 맞대기). 영상의 주인공은 우리 해설이고 원본은 근거.
  - 화면에 출처(채널·프로그램·날짜) 상시 표시 + 설명란 `[원본]` 목록에 주소.
  - 위험 알기: 방송사 영상은 유튜브 **Content ID 신고**(수익이 원저작자에게 가거나 지역 차단)가 날 수 있음. 신고가 오면 그 구간을 카드로 바꾼 판으로 다시 올리는지 사람이 정함. 국내 지상파 뉴스 화면은 신고가 잦아 ②의 마지막.
- **받는 길:** 클라우드는 YouTube 가 봇 확인으로 막음(2026-11-17 다시 확인) — **우회하지 않음.** 클라우드는 영상 찾기(제목·채널·길이 조회)·문장 확인(공식 녹취·기사 인용)·주소와 구간 기록까지 하고, 정부·IR 사이트에서 바로 받을 수 있는 것만 받는다.
  - YouTube 원본은 **사용자 PC** 에서: `python -m ytflow rebuild <프로젝트>` (`clips.cookies_from_browser: chrome`) → `04_assets/footage/` → 다시 렌더.
  - 원본이 없으면 렌더는 멈추지 않고 그 `bite` 장면을 **인용 카드**(원문+번역·이름·출처·"원본 영상: PC 에서 채움")로 그린다 (`ytflow/stages/hybrid.py`). 그날 자동 업로드는 카드판으로 나감 — 원본판을 원하면 PC 단계를 업로드 전(08:00 전)에 끝내야 함.

- **중심축은 시장을 흔든 사건 (v28, 03 §0-3)**: 그 주(그날) 시세를 가장 크게 움직인 사건 하나 → 무엇이 어떻게 되나(파급효과: 회사→업종→순환 금융·연준→한국) → 주의할 점 → 사람들·매체·인사이트의 해석(입장별) → 확인할 신호. 보고서·연준 이야기는 그 사건의 파급 경로 위에서만.
- **모든 심층·분석글 공통 (v26, 03 §0-2)**: ① 알려진 것 → ② 그동안 나온 보고서·발언·행동을 날짜 순으로 엮기(자료마다 의미 한 줄) → ③ 말과 행동 맞대기 → ④ 매체는 어떻게 읽었나 vs 자료를 엮으면 보이는 것 → ⑤ 의미와 확인할 신호.
- **어닝콜 해부**: `03 §0-1` 표 그대로 (숫자와 약속 → 경영진이 한 말 N가지(원문+번역, quote `orig`) → 정리판(`recap`) → 무엇으로 이어지나(해석) → 남은 숙제 → 확인할 약속). 애널리스트 이야기보다 **경영진의 말**이 중심 (2026-11-12 사용자 판정).
- **사건 심층**: 무슨 일(공시) → 왜 지금 → 시장 반응(같이/따로) → 이어지는 곳(증거판) → 남은 불확실성 → 확인할 날짜.

## 6. 화면 문법 (시장 카테고리 개성, `05 §0-7`)
- 기본 팩 slate, 장 표지는 **대시보드 ↔ 듀오톤 사진** 돌려 쓰기, 관계는 **증거판**(`look: board`)
- 사진: 주제에 맞게 (회사 간판·건물·데이터센터·거래소), 위키미디어 공용 **PD·CC0·CC BY** 만 — `python -m ytflow archive commons "검색어"`. 출처 표시 자동. NASA 위성 사진 반복 금지.
- 눈요기(05 §0-3, 권고): 글씨·도형뿐인 장면이 길게 이어지지 않게 → 사진(`layers` photo)·지도(locator)·말에 맞춰 생기는 그림(`motion`) 섞기 (시장 채널은 tilt·dolly·scan·반짝이를 쓰지 않음, v31·v32). 겹친 장면(layers)은 권고 3개 안팎.
- 스타일 섞기는 권고(같은 스타일 3장면 연속·한 스타일 40% 넘으면 다시 보기, 막대·숫자·차트는 data-report 로 묶여 셈 — v34 유동).
- **스캔(빛 훑기)·반짝이 없음 (v32, 2026-11-15 사용자: "스캔하는 듯한 모션그래픽이랑 반짝이는 것도 빼 주세요 — 상황에 안 맞고 과해요, 영상 주제·대본 분위기와 미스매치")** — `fx: scan` 은 시장 채널에서 무시, 숫자 카드의 ✨ 별 없음. 눈요기는 사진·지도·말에 맞춰 생기는 그림(`motion`)으로 (check 도 `motion` 을 눈요기로 셈).
- **시장·산업별 영향 장 (v32, 같은 날 사용자: "이 사태가 어떤 시장과 어떤 산업이 어떤 영향을 받는지")** — 시장을 흔든 사건을 다룰 때는 업종별(경쟁사·고객·공급망·금융·전력·한국 협력사) 시세를 사건 전후로 나란히 놓고, 사건과의 연결(지분·계약·협력 공시)을 1차 출처로 보이고, 같은 기간 겹친 다른 일(실적·금리)을 밝혀 인과를 단정하지 않는다.
- **확대·축소 쓰지 않음 (v31, 2026-11-15 사용자: "자꾸 화면을 확대하고 축소하고 웅웅거리는 거 쓰지 말아 주세요")** — 시장 채널은 장면 안 느린 확대, `fx` tilt·dolly, 차트 확대, 사진 밀기(ken burns), 박자 카메라를 모두 끈다 (hybrid.json `"zoom": "off"` 가 기본, 렌더러 `D.no_zoom`). 화면 변화는 말에 맞춰 생기는 그림·숫자·줄(박자 `motion`, 체크리스트 `t`)과 장면 전환으로만.
- 배경음 기본 없음. **카메라는 억지로 흔들지 않는다 (v30, 2026-11-15 사용자: "정적이라고 했다고 정지 화면에서 굳이 억지로 화면을 웅웅거리며 미세하게 움직이지 않아도 됩니다")** — v27 박자 카메라는 기본 끔(`"camera": "beat"` 로만 켬). '정적'의 뜻은 화면이 흔들리지 않는다는 것이 아니라 **말하는 내용이 화면에 나타나지 않는다**는 것 → 아래 '말하는 것이 화면에 생긴다' 규칙으로 해결.
- **말하는 것이 화면에 생긴다 — 멈춘 화면 금지 (v27, 2026-11-15 사용자 기각: "영상이 정적이다, 멈춰 있는 부분이 많다 — 하는 말은 많은데 45일·60일만 강조돼 있다")**
  - 박자마다 화면이 바뀝니다. 장면의 그림(막대·숫자·줄)에 **없는 숫자·사실을 말하는 박자**에는 그 낱말을 말하는 순간 박자 `motion` 을 붙입니다 — 숫자는 `count`, 사물·주체는 `icon`, 관계는 `arrow`, 강조는 `pulse` (위 '요약 + 움직이는 그림', `ytflow/stages/motion2.py`).
    예: 대금 회수 45일→60일 장면에서 "받을 돈 631억 달러" → `{"t": "631억", "do": "count", "value": "631억 달러", "label": "받을 돈"}`, "회사채 250억 달러" → `count`, "은행" 비유 → `icon` + `arrow`.
  - 한 장면이 25초를 넘으면 6초 안팎마다 새 요소(줄·사물·숫자·카메라 이동)가 있어야 합니다. 3박자 이상인 장면은 둘째 박자부터 `motion` 을 둡니다.
  - 렌더 전 G4 MUST: 화면에 없는 숫자를 2개 이상 말하면서 `motion` 이 없는 박자 0개. 정지 화면 비율(`motion.json`)은 참고만 — 카메라를 흔들어 숫자를 맞추지 않는다 (v30).

## 요약 + 움직이는 그림 (2026-11-13 사용자 확정 방향, docs/25 §8)
- 요약 장면(체크리스트·대결·막대·차트)이 뼈대. **바꾸지 말고 겹친다.**
- 체크리스트는 글을 왼쪽으로 좁히고(`x: 150`, `text_w: 860`) 오른쪽에 박자 `motion`(아이콘·화살표·숫자 세기)을 1~2개씩. 줄마다 `t`(핵심 낱말)로 말할 때 나타나게.
- 그림이 있는 장면은 `anchor` 로 기존 그림 위치를 잡고 화살표만 더한다. 화살표·숫자가 글자와 겹치지 않게 프레임으로 확인.
- 사물은 나타날 때만 움직인다(제자리 흔들림 없음). 색은 장면의 그래픽 팩을 따른다.
- **순서:** 화살표·사물은 가리키는 그림(막대·줄)이 나온 뒤에. 막대·줄은 항목마다 `t`(이름)로 말하는 순간 나타나게 — 대본 순서 = 화면 순서.
