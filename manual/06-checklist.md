# 06. 체크리스트와 검사안 — 반드시 지킬 것

## 검토의 중심은 대본 (2026-11-21 사용자: "앞으로 검토는 길이보단 대본의 구성요소 메뉴얼 대본의 절차 검수 이런거 자체를 지켰나 대본을 중점으로 봐주세요")
에이전트 자체 검사·D2·D4·정기 검토 보고 모두 **길이가 아니라 대본**을 먼저 봅니다. 순서:
1. **대본 절차를 지켰나** — [13-script](13-script.md) §1 쓰기 전 여섯 가지 → §7 자체 검사 → §8 D2 검토 반복(통과 기록) → 그 뒤에만 연출.
2. **구성요소가 모두 있나** — 채널 대본 공식(시장 03 §4·09 §4·§5, 호기심 04 §4, 시사 08, AI 11 §3-1)의 요소마다 있음/없음·어느 장인지 대조표로(`02_script/script_review.md` 의 '구성요소', G4 SHOULD).
3. **사실과 해석** — 13 §4 대조표, 팩트시트에 없는 숫자 없음.
4. 그다음 연출·화면(G5~G7). 길이는 측정값만 보고 판정하지 않습니다(README §2-4).

## 검사 방법
```bash
python -m ytflow check <프로젝트>              # 모든 게이트 (만든 단계까지)
python -m ytflow check <프로젝트> --upto G4    # 대본까지만
```
결과: `05_edit/checklist.md`(사람이 읽는 표) + `05_edit/checklist.json`. **MUST 가 하나라도 실패하면 종료 코드 1** — 다음 단계로 가지 않습니다.
- **MUST** = 반드시. 실패하면 고치기 전에는 렌더·업로드 금지.
- **SHOULD** = 권고. 실패하면 이유를 `REPORT.md` 에 적고 진행 가능.
- **참고(ℹ️)** = 측정값만 보여 줌, 실패 아님. 숫자를 맞추지 않고 표시된 곳을 원리(`05` §0-0)로 다시 봅니다.
- **EYE** = 사람(또는 에이전트)이 눈으로 확인. 자동 검사 불가 → 확인 후 `05_edit/checklist_eye.md` 에 체크.

> **채널 전용 검사**는 그 채널에만 걸립니다: 매일 시장 → `09-market-daily.md` §9, 호기심 롱폼 → `04-curiosity.md` §7, 시사 → `08-issues.md` §6.

2. 프레임 시트에서 잘린 글자·겹친 선·빈 화면을 찾는다.

6. **서사 QA** (2026-11-21 사용자 제공 영상 진단·대본 검토): 첫 질문이 분명한가 · 중반에 새로 알게 되는 것이 있는가(이미 들은 말을 사례만 바꿔 반복하지 않는가) · 반전이 늦지 않은가 · 결말이 도입의 질문을 회수하는가.
7. **연출 QA**: 화면에 나온 물체·행동이 설명에 기여하는가(그 장면을 지우면 이해가 줄어드는가) · 같은 그림·같은 문서형 카드가 상태 변화 없이 반복되지 않는가 · 인물·소품·사건의 연속성이 유지되는가.
> 검사 통과(기술 QA)는 완성도의 증거가 아니다. 기술·서사·연출 QA 는 서로 다른 통과 조건으로 따로 기록한다.
