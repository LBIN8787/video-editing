## 1. 애니메이션 무대(`stage`) vs 이야기 그림판(`story`)

### 애니메이션 무대 `stage` — 한 화면 = 한 순간. 주인공이 대본의 동사를 '연기'한다
**쓰는 때**
- 주인공(사람·로봇·동물·사물)이 무언가를 '하는' 박자 — 앉다·쓰러지다·닫다·집다·미끄러지다
- 반전·깨달음을 그림의 움직임 하나로 보여 줄 때 (시소가 넘어감·모양이 바뀜)
- 두 주인공의 대결·대비 (체스 말 vs 티셔츠)
- 처음·가운데·끝에 같은 주인공을 다시 불러 모티프로 묶을 때
**쓰지 않는 때**
- 여러 사실을 한 장에 모아 '전체 그림'을 봐야 할 때 → story
- 숫자 비교가 핵심 → number 묶음
- 실제 인물·사건의 증거 → evidence 묶음

### 이야기 그림판 `story` — 큰 종이 한 장에 이야기가 '쌓인다'. 카메라가 다음 자리로 옮겨 감
**쓰는 때**
- 여러 장소·인물·날짜가 이어져 마지막에 한 장으로 모아 볼 때 (지도처럼 펼쳐진 사건의 흐름)
- 관계·계보·연표처럼 앞에 그린 것이 뒤의 의미가 될 때
- 장 끝에 지금까지 그린 것을 한 화면에 모아 대비·질문으로 닫을 때 (카메라 full)
- 주인공의 '행동'보다 '무엇과 무엇이 엮였나'가 이야기의 핵심일 때
**쓰지 않는 때**
- 한 순간의 행동·반전 → stage
- 요소가 6개를 넘어 콜라주가 될 때 (v22 기각 원인) — 장면을 나누거나 stage 로
- 글자 쪽지·소제목으로 대본을 다시 쓰게 될 때

**함께:** 같은 영상에서 섞어 쓴다 — 박자가 '하는 일'이 정한다 (사람이 한다 → stage, 쌓아 엮는다 → story). 호기심은 v60 부터 실사 B-roll·모션그래픽이 먼저이고 stage·story 는 자료가 없는 박자의 대체 수단 (04 §0-8)

| 실사 위 요청 칩 | 이미 있음 | 같은 장소의 여러 요청·사용 사례를 소개할 때 | 얼굴·핵심 동작·자막을 가리지 않게 위치 조정; 실제 발언처럼 보이는 예시에는 고지 |
| 문서 스포트라이트 | 이미 있음 | 기사·공식 문서에서 근거 문장을 짚을 때 | 원문·출처를 확인; 텍스트 재구성은 실제 캡처와 구별; 어둡힌 문단 대비 경고는 수동 검토 |
| 두 줄 장 표지 | 이미 있음 | 앞 장의 결론에서 다음 질문으로 넘어가는 자리 | 매 장면에 반복하지 않고 읽을 시간·배경 대비를 확보 |
| 원 모양을 잇는 아이리스 | 이미 있음 | 금고 보호 범위 등 원 모양이 다음 이야기로 이어질 때 | 현 구현은 바탕색을 거쳐 열림; 원 안에 다음 장면이 곧바로 보이는 합성은 미구현 |
| 사건 이후 누적 (시간선 + 쌓이는 카드) | 이미 있음 | 사건 뒤에도 계속됐다 · 그 이후 몇 번 — 시간 조건과 수량을 한 화면에 | 카드 간격은 시간 간격이 아니라 개수 (날짜를 붙이지 않는 한). 보고서 주장이면 제목에 출처 |
| 두 값 사이 간격 (괄호·점선 기준) | 이미 있음 | 두 값의 차이가 이름을 가진 개념일 때 — 마진·스프레드·괴리·차익 | 단순화한 설명 모델이면 '예시 값'·'개념도'를 표시 |
| 전체 중 몫 (채워지는 막대 + 비교 눈금) | 이미 있음 | 전체 중 얼마를 차지하나, 합치면 기준을 넘나 | 분모(무엇의 100%인지)를 화면에 남김 |
| 자유 무대 (인물·물체가 움직이며 설명) | 이미 있음 | 누가 무엇을 누구에게 넘기나, 제도·구조가 어떻게 작동하나 — 위 세 틀에 안 맞는 상황 설명 | 실제 인물은 권리가 확인된 사진만, 없으면 실루엣 + 이름표. 캐릭터 몸짓 애니메이션은 stage·illust |
