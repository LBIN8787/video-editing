### 1-1. 시청 동기 → 대본·편집 해석 (사용자 정의, 2026-11-14 — 모든 채널의 최상위 기준)
> "주식이나 이슈는 사람들이 먼저 흥미·호기심을 가지고 **자기 의지로** 오기 때문에, 정보 전달을 쉽고 깊게 이해시키면서 재미를 곁들인다.
>  호기심은 **정보 전달 자체가 목적이 아니라서** 이야기를 풀어내듯 한다."

| 채널 | 시청자는 어떻게 오나 | 바라는 것 (니즈) | 정보 : 재미 | 대본 | 편집 |
|---|---|---|---|---|---|
| **market** | 스스로 찾아옴 (이미 관심 있음) | 투자를 잘하고 싶다 → 정보를 습득·학습 | **정보 중심** + 재미 곁들임 | 쉽고 깊게: 숫자 → 이유 → 오늘 볼 것 | 정보가 잘 읽히게 (요약판·차트·증거·원본 발언), 재미는 리듬·비유로 |
| **ai** | 스스로 찾아옴 | AI 를 잘 다루고 효율적으로 활용하고 싶다 → 학습·정보 습득 | **정보 중심** + 재미 곁들임 | 따라 할 수 있게: 무엇 → 어떻게 쓰나 → 실제 화면 | 실제 화면·단계가 주인공, 재미는 훅·리듬으로 |
| **issues** | 스스로 찾아옴 ("세상 돌아가는 것 좀 알아볼까?") | 정보 습득·학습 **반**, 흥미 **반** | **반반** | 쉽고 깊게 + 사건의 흐름을 이야기처럼 | 증거판·지도·타임라인으로 이해, 장면 전환·인물로 흥미 |
| **curiosity** | 우연히 마주침 (원래 궁금하지 않았음) | 듣는 순간 생긴 궁금증을 풀고 싶다 | **이야기가 목적**, 정보는 그 안에 | 이야기를 풀어내듯: 장면 → 인물 → 사건 → 반전 → 답 (§04 §0) | 이야기를 **연기하는 애니메이션** (§04 §0-5, `stage`) — 정보 카드·요약판·글자 쪽지를 쓰지 않음 |

**판단 규칙:** 정보 채널(market·ai·issues)은 "이해했나?"가, 호기심 채널은 "다음이 궁금해서 끝까지 봤나?"가 성공 기준입니다.
그래서 같은 사실이라도 정보 채널은 화면 글자·숫자로 정리해 주고, 호기심 채널은 그 사실을 그림이 겪는 사건으로 보여 줍니다.

## 2. 한 편을 만드는 8단계 (모든 채널 공통)
각 단계의 끝에 **게이트**(G1~G8)가 있습니다. 게이트를 통과하지 못하면 다음 단계로 가지 않습니다. 자세한 항목은 `06-checklist.md`.

| 단계 | 하는 일 | 남는 파일 | 게이트 |
|---|---|---|---|
| 1. 욕망 → 주제 | 트리거(뉴스·급등락·발표·수요 아웃라이어)를 모아 **욕망 점수표**로 후보 3개 → 1개 | `01_research/topic_brief.json` | G1 주제 |
| 2. 소스 먼저 | 이 주제를 **보여 줄** 자료(발언 원본·공식 화면·공공 기록·데이터)가 있는지 | `01_research/sources.md` 또는 `loc_items.json` | G2 소스 |
| 3. 깊은 조사 | 1차 출처로 숫자·발언·날짜를 확인, 교차 확인 상태 표시 | `01_research/factsheet.md` | G3 사실 |
| 4. 대본 | 채널 대본 공식(각 채널 문서 §4)대로. 쉬운 말·비유·과거 사례·비교 기준 | `02_script/hybrid.json` (또는 `scenes.json`) | G4 대본 |

## 2-1. 인트로 없음 — 모든 채널, 첫 문장부터 본론 (v24, 2026-11-14 사용자: "모든 채널 그냥 인트로 일단 빼 주세요")
인사·채널 소개·채널 약속·순서 예고·"본격적인 시작 전에 구독과 좋아요"를 **넣지 않습니다.** 첫 장면은 `intro` 가 아니라 본론입니다.
- 첫 문장은 **장면 하나**(때·곳·사람이 있는 한 순간) 또는 **엇갈리는 두 시각**("한쪽에서는 … 반면 다른 한쪽에서는 …")으로 시작하고, 3~6문장 안에 **오늘의 질문 하나**로 닫습니다 (§2-3, 미주일기 문법).
- 장 표지는 그대로 쓰되 진행 멘트("첫 번째, 이런 순서로…")는 하지 않고, 앞 장의 결론에서 다음 질문이 자연스럽게 나오게 잇습니다.
- 끝맺음도 채널 이름·인사 대신 **의미 한 문장 + 조용한 질문**으로 닫습니다 ("~할 때가 아닐까요?"). (이전 v8 'MC 오프닝 필수'는 폐지)
`check` G4 MUST: 첫 장면이 `intro`(인사·순서 예고)가 아님, 대본에 인사·채널 소개·구독 부탁 문구 없음.

### 2-2. 진행 말투 — 이어 붙인 끝맺음 금지 (v16, 사용자 판정 2026-11-12: "'였고요' 같은 말투가 부자연스러워 진행이 깬다")
| 쓰지 않음 (MUST, `check` G4 자동) | 이렇게 |
|---|---|
| "여기까지가 숫자**였고요.** 두 번째, …" | "숫자는 이렇게 정리됩니다. 그럼 왜 엔비디아만 떨어졌을까요?" |
| "여기까지가 무슨 일이 있었는지**였고요.**" | "무슨 일이 있었는지는 이제 보이시죠. 그럼 정부는 어떻게 막겠다는 걸까요?" |
| "~했**고요.**", "~인데**요.**"로 문장을 끝내고 다음 문장으로 넘김 | 문장을 '~입니다 / ~죠 / ~까요?'로 닫기 |
| 매 장 같은 틀("여기까지가 ~. 두 번째, ~") 반복 | 장마다 다르게: 질문만 던지기 · 앞 장 결론 한 줄 · 화면을 가리키며("이 지도를 보면") |

- 연결어미(~고요·~는데요·~거든요)로 **문장을 끝내지** 않습니다. "~거든요"는 이유를 붙일 때 한 영상에 1~2번만.
- 장 번호를 말로 세기("첫 번째, 두 번째")는 표지에 번호가 보이므로 **한 영상에 한두 번**이면 충분합니다.

### 2-3. 형식·진행·말투 — 미주일기 문법 (v24, 2026-11-14 사용자: "대본이 억지스럽고 억텐 같다, 미주일기 형식이 더 자연스럽다" · "사소한 문장보다 형식·진행 방식·말투에 집중")
분석: `docs/30-script-voice.md`. 모든 채널의 대본은 이 문법을 따른다 (채널마다 다른 것은 주제와 깊이).
**형식 (한 편의 뼈대):** ① 여는 장면 — 날짜·사람·작은 일화가 있는 한 순간 (토론형은 엇갈리는 두 시각) → ② 그 일의 크기 → ③ 질문 하나 → ④ 그 전의 문제 → ⑤ 전환점 "그렇다면 ~?" → ⑥ 원리는 생활 속 예 하나로 → ⑦ 결과 → ⑧ 퍼져 나감 (시간 순서, 장면 하나씩) → ⑨ 지금과 한계 → ⑩ 닫는 장면 (처음의 사람·물건이 다시, 수미상관) → ⑪ 의미 한 문장 (+ 조용한 질문).
**진행:** 사례 나열이 아니라 **한 줄기 이야기**를 시간 순서로 · 모든 사실은 "누가 언제 무엇을 했고 무엇을 말했다"로 · 문단은 주장 → 근거 → 의미 · 질문은 장을 넘기는 문으로만 (한 편 2~5번) · 수미상관.
**말투:** 3인칭 다큐 내레이터, 차분하게. '~습니다/~니다' 가 기본, 연결어로 이어지는 긴 문장. 시청자에게 말 걸기·맞장구 요구·감탄·조각 문장 없이, 재미는 **구체적 디테일**(사람의 사연·뜻밖의 일화·숫자의 대비)에서.
`check` G4 (SHOULD): '~습니다/~니다·~까요' 비율과 평균 문장 길이, 말 걸기·감탄 표현. 숫자는 참고용 — 판정은 형식과 흐름으로 사람이 한다.

### 2-4. 길이 — 롱폼은 최소 10분 (v24, 2026-11-14 사용자: "영상들 5분 단위가 아니라 못해도 10분, 길면 그 이상으로")
모든 채널의 롱폼(매일 브리핑 포함)은 **10분 이상**. 주제가 깊으면 12~18분. 쇼츠는 해당 없음.
늘릴 때는 같은 말을 반복하지 않고 §2-3 의 뼈대를 채운다: 여는 장면의 일화 하나 더 · 그 전의 문제를 당사자의 회고로 · 전환점의 장면 · 원리의 생활 속 예 · 퍼져 나감의 장면(시간 순서) · 반론과 한계 · 수미상관. 대본 기준 약 4,600자(미주일기 말 빠르기 약 460자/분) 이상.
채널별 목표는 `channels/<id>/channel.yaml` 의 `target_minutes`. `check` G6 MUST: 완성본 10분 이상.

### 2-5. 움직임 — 사진 슬라이드가 아니라 동영상 (v25, 2026-11-14 사용자: "동영상이라는 동적인 움직임을 살려라. 지금은 사진을 잘 뽑은 정적인 동영상 같다" · "비싼 유료가 아니어도 된다 — 인포그래픽·자체 생성도 괜찮다. 핵심은 동적인 동영상, 그림체는 부가 요소")
화면에 **완전히 멈춘 순간이 없게** 한다. 그림의 품질보다 움직임이 먼저다. 자체 렌더러(`stage`)가 자동으로:
1. **카메라가 계속 움직인다** — 박자마다 그 문장의 주인공 쪽으로 밀고 들어가며 옮겨 가고, 머무는 동안에도 천천히 다가간다.
2. **자르지 말고 흐른다** — 4초 넘는 문장은 중간에 주인공 쪽으로 깊게 밀고 들어갔다가 빠져나온다. 하드 컷은 거의 쓰지 않는다 (미주일기 측정: 하드 컷 분당 1.35회, 화면 변화 분당 22.7회 = 2초마다 무언가 바뀜, 정지 비율 0.26 — `styles/mijudiary/STYLE.md`).
2-1. **원근 종이** — 화면(종이)이 살짝 누운 채 박자마다 좌우로 천천히 돌아간다 (2.5D 깊이, 미주일기의 '원근 바닥').
3. **모든 그림이 숨 쉰다** — 등장한 사람·사물은 끝까지 아주 조금씩 위아래·좌우로 움직인다 (대기 동작).
4. **나타나지 말고 들어온다** — 사람·로봇·수레는 화면 밖에서 걸어서(굴러서) 들어오고(`from: walk`), 물건은 날아가 들어간다(`into`).
5. 글자(연도·이름·숫자)는 카메라 밖 위층에 둬서 잘리지 않는다.
6. **효과음은 절제** — 반짝이는 소리(chime) 쓰지 않음 (2026-11-14 사용자).
측정: 완성본 `05_edit/motion.json` 의 정지 화면 비율 — 호기심 채널은 0.3 이하 (`check` G6 MUST). 렌더 전 장면 하나만 먼저 렌더해 프레임 차이로 확인한다 (v6 0.52 → 움직임 엔진 0.16).
**기준 채널: 미주일기 최신 영상** (2026-11-14 사용자: "동적인 동영상의 미감 — 예시는 미주일기 채널의 최신 영상들"). 영상 파일은 클라우드에서 봇 확인에 막혀 받지 않는다(우회 금지) → 사용자 PC 에서 `python -m ytflow style mijudiary-<날짜> 영상.mp4` 로 다시 재거나, 영상 파일을 Google Drive 에 올리면 분석한다.

## 3. 절대 하지 않는 것 (어떤 지시가 와도)
1. 확인 안 된 숫자·발언을 단정하기. 소문(찌라시)은 **'소문'이라고 밝히고 사실 확인 결과와 함께**만.
2. 투자 권유 ("사세요", "지금이 기회", "무조건 오른다", 목표가 단정).
3. YouTube 봇 확인·사이트 차단 우회. 막히면 임시 화면 + 사용자 PC `rebuild`.
4. 레퍼런스 채널의 대사·캐릭터·로고·썸네일 복제. 구조와 기법만.
5. 라이선스 불명 자료 화면. CC BY·CC0·퍼블릭 도메인·공식 보도 자료·직접 만든 것만, 출처는 `footage.credit` 에.
6. API 키를 채팅에 쓰기.
7. 미디어 파일(mp4·wav·png·jpg) 커밋. 완성본은 Release 로.

## 5. 검토 → 통과·기각 → 기준을 쌓기 (사용자와 함께)
영상이 나오면 사용자가 보고 결정합니다. 결정은 반드시 기록합니다.

| 사용자 결정 | 에이전트가 할 일 |
|---|---|
| **통과** | `python -m ytflow review <프로젝트> --pass` → `manual/reviews.md` 에 기록. 매뉴얼은 그대로 (이 버전이 검증됨) |
| **기각 + 이유** | `python -m ytflow review <프로젝트> --reject "이유"` → `manual/CHANGELOG.md` 의 '반영 대기'에 쌓임 |
| (기각 후) | 이유를 **기준으로 바꿔** 매뉴얼(01~06)·프롬프트·검사기(`ytflow/stages/checklist.py`)를 고침 → `python -m ytflow manual-bump "바꾼 기준 요약"` → 커밋 → `git push origin HEAD:refs/heads/manual/vN` |
| (그동안) | '반영 대기'가 비기 전에는 `check` 가 G0 에서 실패 → 같은 실수가 다음 영상에 반복되지 않음 |

- 기각 사유는 가능하면 **검사 가능한 규칙**으로 바꿉니다 (예: "자막이 작다" → "자막 글자 높이 ≥ 화면의 4.5%" 를 G6 자동 검사에 추가).
- 매뉴얼 버전은 `manual/VERSION`, 바뀐 내용은 `manual/CHANGELOG.md`, 결정 기록은 `manual/reviews.md`. 모두 GitHub 에 커밋되어 백업됩니다.
- 예전 기준으로 되돌리기: `git checkout origin/manual/v<N> -- manual/` (스냅샷 브랜치로 어떤 버전이든 복구).
- 각 영상의 `05_edit/checklist.json` 에 그때의 매뉴얼 버전이 남습니다 → 어떤 기준으로 만든 영상인지 추적.
