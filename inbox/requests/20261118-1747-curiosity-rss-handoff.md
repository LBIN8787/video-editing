사용자의 최신 취지: 심리 RSS만이 아니라 뉴스레터/RSS처럼 지속 들어오는 정보 수집·정리 전체를 피클에게 맡기고, 실제 작업을 지시받은 모델은 공통 자료를 읽어 활용하도록 합니다. 사용자 워딩: “제가 작업을 맡기면 제가 작업을 맡긴 모델이 일을 할 수 있기를 바래요”. 역할을 더 정확히 구분합니다. 피클은 들어오는 뉴스레터/RSS 소재 수집·정리·분류 담당입니다. 실제 심층조사·팩트검증·분석·대본·영상 제작은 해당 작업을 맡긴 에이전트가 공통 자료를 이어받아 수행합니다. 피클에게 제작이나 심층조사까지 맡기는 것이 아닙니다. 아래 기존 공용 수집 체계를 확인하고 인수 상태와 다음 수집 결과를 알려 주세요. 사용자가 추가로 피클의 소재 정리·분류를 6시간 간격으로 수행하도록 명시적으로 요청했습니다. 아래 최신 설정 요청이 이전의 스케줄 변경 금지 설명을 이 범위에서 대체합니다. 요청함이 설정 변경을 직접 처리하지 않는다면 사용자에게 승인 요구를 반복하기보다는 이 명시 지시를 기존 공식 피클 운영 절차로 인계하고, 실제 적용 여부를 구분해 회신하세요. 코드·제작 매뉴얼·모델 라우팅은 변경하지 않습니다.

## 확인·수집 범위
0. 기존 뉴스레터/RSS 전체의 구독·검증·정리 현황과 실패를 포함해 지속 수집·정리 담당 인수 여부를 확인. 심리 RSS만의 별도 운영으로 한정하지 않기.
1. 기존 수집 담당/실제 스케줄 활성 여부와 최신 main 반영 여부를 확인. 중복 예약 생성 금지.
2. 기존 허용된 수집 방식으로 새 심리·호기심 RSS 소재를 모으고 기존 공용 inbox에 중복 없이 합류했는지 확인.
3. 들어오는 소재를 심리학·일상 원리·과학·행동·역사 등으로 분류하고 제목·링크·발행시각·출처·중복 여부·관련 채널·후속 조사 필요 여부를 남깁니다. 어떤 소재를 조사/제작할지의 실제 작업은 사용자가 지정한 에이전트에 남겨 둡니다.
4. 접근 실패는 그대로 남기고, 새 구독·계정·권한·결제·영상 제작·공개는 하지 않기.

## 최신 사용자 요청: 6시간 간격 운영
- 피클이 뉴스레터/RSS 들어오는 소재를 **6시간마다 수집·정리·분류**하도록 설정해 주세요.
- 먼저 현재 피클 작업 ID·활성 상태·주기를 확인합니다. 같은 역할의 기존 05:40 KST 작업이 실제 있으면 새 작업을 중복 생성하지 않고 그 작업을 수정하는 방식을 우선합니다.
- 기존 아침 수집 기준점을 보존할 수 있다면 한국시간 **05:40 / 11:40 / 17:40 / 23:40** 하루 4회로 6시간 간격을 적용합니다. 사용자가 지정한 것은 6시간 간격이며 이 시각은 기존 05:40 문서 기록을 보존하기 위한 제안입니다.
- 영상 제작/업로드 스케줄, 다른 수집 작업, Claude/Codex 실행 모델은 변경하지 않습니다. 다른 작업과 결합돼 안전하게 분리할 수 없으면 실제 충돌과 필요한 변경만 보고합니다.
- 기존 사용 허가된 뉴스레터/RSS만 대상으로 하며 새 구독·결제·계정 연결·권한 확대는 하지 않습니다. 정상 실행마다 알림하지 말고 실패·중요한 설정 변경·첫 적용 확인을 보고합니다.
- 결과에 실제 작업 ID, 적용된 시간대/주기, 다음 실행 시각, 중복 작업 처리 여부, 최근 실행 결과/공용 산출물 위치를 기록합니다.
- 이 파일을 읽었다는 확인과 **실제 스케줄 적용**, **첫 실행 성공**을 각각 구분해 주세요.
