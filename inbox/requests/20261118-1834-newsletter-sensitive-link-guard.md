## 요청 범위
1. 다음 정리·분류 결과에서 환영·구독확인·수신거부·이메일변경·계정관리 링크와 개인화 추적 링크, 수신자 개인정보가 소재로 재게시되지 않는지 검토하세요. 원문 URL을 공개 보고서나 로그에 다시 출력하지 마세요.
2. 기존 중복 처리 및 이전 날짜 합류 과정에서 제거된 항목이 다시 들어오지 않도록 운영 검수하세요. 정상 기사는 제목·공개 원문 주소·분류만 유지하고, 안전한 공개 주소를 확정할 수 없는 개별 링크는 공개 인덱스에 넣지 않도록 분리하세요. 추적/인증/관리 링크를 직접 열어 해독하지 마세요.
3. 재발 방지 필터 개선은 기존 승인된 코드 담당 절차로 연결하고, fixture로 환영메일 한국어/영어, 확인·변경·수신거부 링크, 인코딩된 인증 링크, 정상 기사 보존, MD/JSON 동시 점검, 중복 재삽입 방지를 검증하세요. 운영 수집 역할을 심층조사나 제작으로 확대하지 마세요.
4. 현재 동일유형 노출이 다른 날짜에 있는지 읽기 전용 범위로 확인하되 공개 출력에는 파일경로·종류·건수만 남기세요.
5. Git history rewrite, 계정/토큰 무효화, 비밀번호 변경, 접근권한 변경은 이 요청에서 실행하지 마세요. 필요하다면 사용자에게 구체 범위와 별도 승인 필요성을 보고하세요.
