# 저장 목적 정정: Git + Drive 병행, 로컬 부담 최소화

## 사용자 최신 원문
“깃과 드라이브 둘다 보관 할 수 있도록 해줘 내 의도는 그거야 즉 깃에 보관하되 깃에 보관하기 힘든 부분은 드라이브쪽을 활용하라는거야 로컬드라이브 부담을 줄이는게 목적이고”

## 뜻하는 것 / 뜻하지 않는 것
- Git에 적합한 코드·문서·설정·기획·텍스트 분석은 Git으로 버전 관리한다.
- 대용량 영상·오디오·반복 프레임·원자료 묶음처럼 Git 이력에 부담을 주는 것은 Drive로 보관한다.
- 필요하면 양쪽에 사본을 둘 수 있으나, 모든 파일의 이중 저장을 의무화하지 않는다.
- “AI 작업물 전부 Drive”를 Git 금지 또는 모든 작은 문서의 Drive 사본 의무로 해석하지 않는다.
- 핵심 목적은 사용자 PC 로컬 저장공간 부담 감소다. 모든 파일을 영구 로컬 보존하거나 Git 이력에 대형 바이너리를 쌓는 것은 목적에 어긋난다.
- 이 지시는 저장 위치 정정이지 기존 파일 삭제·공개 범위 확대·자격증명 게시 권한이 아니다.

## 담당자에게 요청하는 좁은 반영안
1. AGENTS.md 저장 위치 조항을 위 원칙으로 바꾸고 커밋 대상 조항과 일치시킨다.
2. docs/09-storage.md §0에 Git/Drive 역할 분담을 명시한다. Release는 공개·권리상 적합한 기존 산출물의 선택 경로이며 Drive 대신 강제하지 않는다.
3. skills/ref-watch-ego는 큰 프레임/클립을 Drive에 두고, 작은 분석 Markdown과 소스·검수·파일 목록은 Git에 둘 수 있게 정합성을 맞춘다.
4. inbox/requests/README.md는 피클 소유이므로 담당자끼리 조율한다. 작은 공개 가능한 CSV/캡처만 Git 첨부 허용, 큰/민감한 첨부는 비공개 Drive. 현재 README의 모든 첨부를 done/artifacts에 커밋한다는 표현은 선택 규칙으로 정리한다.
5. Git에는 보관 위치와 판본·크기·검수 상태 등 필요한 최소 메타데이터를 남기되, 공개 저장소에 비공개 데이터나 접근 토큰 포함 URL을 넣지 않는다.
6. 원본은 git 기존 커밋/버전으로 보존하고, 단일 매뉴얼 담당이 잠금을 확보한 뒤 좁은 변경을 반영한다. 다른 제작/연출 기준은 바꾸지 않는다.

## 검수 기준
- 코드/문서의 Git 저장과 큰 파일의 Drive 저장이 서로 충돌하지 않는다.
- 공개 Git 여부·자료 이용권·개인정보를 확인한 후에만 첨부한다. 로그인 화면, 비공개 스튜디오 자료, 개인정보, 자격증명은 공개 Git 금지.
- Drive 저장이 곧 PC 용량 0을 뜻하지 않는다. 앱 캐시·오프라인 사본 여부를 따로 확인한다.
- 업로드/동기화 완료와 보관본 재열기 확인 전 로컬 원본을 제거하지 않는다. 삭제는 별도 허용과 복구 가능성을 확인한다.
- PC Drive 동기화는 현재 중지 상태를 유지한다. 저장규칙 변경이 동기화 재개 승인이 아니다.
- 이 제안은 정책 반영 대기이며 파일 이전·삭제·환경변수 변경·프로그램 설치·미디어 업로드를 실행한 기록이 아니다.
