# 70. 인사이트 수집 — 자리 → 판단 → 주제 (2026-11-26)

> 사용자: "그렇다면 이 인터뷰자료나 소스수집은 어떻게 할 것인가요? 여러 방송국이나 매체들을 주기적으로 봐야할까요?"
> → "다른 사람들의 인사이트 유명 기술자 실리콘밸리의 기술 등등 결국 저는 누군가의 인터뷰 인사이트 등 좀 더 기존보다 폭넓게 다루고자 합니다. 기술 인사이트 시장 인사이트 등 말이죠 사람을 감시하기보다는 좀 더 폭넓게 다루고싶어요"
> → "네 그대로 만드시고"

## 왜
- 분석 영상의 주어는 소식이 아니라 **'앞으로 어떻게 되나'에 대한 누군가의 판단**이고, 소식은 그 판단의 근거다(manual/09 §5-00, v137). 그래서 모으는 단위도 소식이나 사람이 아니라 **판단**이다.
- 원본 레이더(docs/63)는 정해 둔 35명을 이름으로 찾는다 — 목록 밖의 기술자·창업자·전략가는 놓친다. 그리고 11-23 한 번만 돌고 자동 작업에 들어가 있지 않았다.
- 사람이 방송국·매체를 돌아보는 대신, **인사이트가 나오는 자리를 매일 자동으로 넓게 훑고** 사람(에이전트)은 걸러진 후보만 본다.

## 흐름
| 단계 | 무엇 | 비용 |
|---|---|---|
| ① 자리 훑기 | `config/insight_venues.yaml` 의 자리(기술: Dwarkesh·No Priors·BG2·Latent Space·a16z·YC·회사 공식 … / 시장: CNBC·블룸버그·Odd Lots·Colossus·골드만·모건스탠리·이코노믹 클럽·연준 …)의 이번 주 새 영상. 12분 미만(클립)·해설 말투 제외 | 목록·RSS 만, 내려받기 없음 (약 2~3분) |
| ①-2 목록 밖 | 이번 주 검색(조회가 튄 인터뷰·강연, 영어), 해커뉴스 첫 화면의 강연·인터뷰 | 목록만 |
| ② 1차 거르기 | 제목·설명으로: 앞으로에 대한 판단이 있나 · 주제(질문 한 줄) · 누가 · 세기(0~3) · 경로(market/ai/issues) | LLM 간단 티어 (`config/models.yaml` insights: simple) |
| ③ 판단 뽑기 | 점수 높은 몇 편만 자막을 열어 판단 문장 원문·번역·몇 초·근거·시간표·입장 | 자막 1회씩 (429 면 건너뜀) |
| ④ 주제별 장부 | `inbox/insights/ledger.json` — 주제(질문) 아래 판단이 쌓임. 보고 `inbox/insights/<날짜>.md`: ① 영상 후보 ② 오늘 높은 순 ③ 주제별 장부 | — |

**점수** = 자리 무게^0.5 × (1 + 판단 세기) × 새로움(올린 지 10일이면 0.4) × 조회(로그) × 이름 있는 사람이면 1.3. 사람 이름은 거르는 조건이 아니라 가산점만.

**영상 후보** = 한 주제에 서로 다른 사람의 맞서는 판단(→ 맞대기 편) 또는 한 사람의 날짜·숫자가 있는 판단 둘 이상(→ 드러켄밀러형 편, manual/09 §5-00).

**경로:** 기술이 돈·기업·시장을 어떻게 바꾸나 → 시장 채널 / AI 를 쓰는 법·일의 변화 → AI 채널 / 사회·제도 → 시사.

## 쓰는 법
```bash
python -m ytflow insights                  # 전부 (아침 작업이 매일 돌림)
python -m ytflow insights --no-llm         # 자리 훑기만
python -m ytflow insights --extract 3      # 자막까지 열 후보 수 (2시간 감시는 3)
python -m ytflow insights --mark <원본id> made --our <우리 유튜브 id>   # 공개→우리 업로드 걸린 날 기록
```
자리 늘리기: `config/insight_venues.yaml` 에 한 줄(`handle` 은 @이름, 없으면 UC… 채널 id). 찾지 못하면 실행 로그에 '! 자리 못 찾음'.

## 자동 작업에 들어간 곳
- 아침 `market-daily` 3-1: 매일 한 번 전부 → 같은 질문이면 `deep-topics.md` 쌓인 단서에도.
- 2시간 `market-deep-watch` 훑기 0: 오늘 결과를 읽고, 6시간 넘었으면 `--extract 3` → `인사이트형` 후보.
- 판단 −1: 영상의 주어 = 앞으로에 대한 판단, 장부에 판단·반대 판단·원본이 갖춰지면 만든다.
- 검수: **자동 공개하지 않음** — 비공개로 올리고 제목·썸네일 승인 요청(2026-11-25 규칙, 11-26 "네 그대로").

## 지키는 것
- 결과는 단서. 대본의 판단 문장은 원본(영상 ?t=초)에서 다시 확인하고, 인용은 짧게(manual/09 §3-5: 본인·회사 공식은 길어도, 방송사는 한 구간 20초·한 편 60초 안팎) + 해설.
- 봇 확인·요청 제한(429)은 우회하지 않고 건너뜀. 영상·음성은 받지 않음(자막 글만).
- LLM 이 뽑은 원문은 자막 그대로여야 함 — 자막에 없는 말은 만들지 않게 지시, 그래도 대본 전에 원본으로 대조.

## 측정 (다음에 볼 것)
- 원본 공개 → 우리 업로드 걸린 날(`--mark … --our`)과 조회수 — 빠를수록 나은지. 채널 운영 분석(`channel-ops`)이 장부의 `lag_days` 를 읽어 docs/63 표에 더한다.
- 자리별로 영상 후보가 실제로 나온 비율 — 한 달 동안 후보가 0인 자리는 빼고, 목록 밖에서 자주 잡힌 채널은 자리로 올린다.
