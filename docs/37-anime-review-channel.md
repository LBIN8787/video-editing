### 1-3. 여기서 얻은 판단 (처음 판단 — 사용자 결정으로 §2 소개형으로 바뀜)
> 아래는 분석형을 본체로 권했던 처음 판단. 소개형으로 가면서 C(전편 몰아보기)의 위험은 '앞 3화·결말 없음·내레이션 80%' 규칙으로 줄이고, A(분석)는 보조 회차로 남긴다.

1. **들어갈 자리: A(비교·연출 분석)를 본체로, B(보기 전 총정리)를 시기성 회차로.**
   - A는 같은 규모(2만) 채널이 이미 증명했고, 저작권 구조가 가장 안전하다.
   - B는 방영·개봉 일정에 맞추면 검색 유입이 크다. 다만 줄거리를 길게 틀면 C와 같아지므로 **"원작 설정 + 결말 해석"을 내 화면(관계도·연표) 중심으로** 만든다.
2. **C(전편 몰아보기)는 하지 않는다.** 숫자는 크지만 채널 하나가 경고 3번에 사라지는 구조이고, 저장소 규칙(차단 우회 금지)과도 맞지 않는다.
3. 제목은 **"A vs B"**, **"○○가 좋은 N가지 이유"**, **"보기 전 ○분 총정리"** 가 반복해서 통했다. "왜·이유"만 단독으로 쓴 제목은 배수가 낮았다(0.88) → 질문형은 비교·숫자와 묶는다.

## 2. 채널 설계 — 소개형

| 항목 | 정함 |
|---|---|
| 욕망 | **"볼지 말지 빨리 정하고 싶다 / 재밌는 부분만 몰입해서 보고 싶다"** — 새 브랜드로 둘지 curiosity 아래 라인으로 둘지는 매뉴얼 담당 제안함 |
| 형식 | 롱폼 10~15분 (앞 1~3화) · 같은 소재 쇼츠 2편 · 가끔 분석형 |
| 주기 | 주 2편 |
| 편집 | `recap` — 원작 화면 위 내레이션(원작 소리 12%로 낮춤), 훅·명대사·반전만 원작 소리 그대로, 큰 자막 |
| 목소리 | 3인칭 다큐 내레이터 '~습니다', 인트로 없음 |
| 소스 | 사용자가 정식 구독·구매한 에피소드 → `projects/<프로젝트>/04_assets/episodes/` (커밋 안 함) |

### 2-1. 편집의 핵심 5가지 (이 형식의 기술)
1. **장면 고르기** — 에피소드에서 발단 → 갈등 → 반전 → 고조만, 전체의 10~20%.
2. **내레이션으로 잇기** — 잘라 낸 시간은 한두 문장으로 ("사흘 뒤, 그는…"). 내레이션이 끌고 화면이 따라온다. 대사를 읽어 주지 말고 속마음·의미를 덧붙인다.
3. **소리 살릴 곳/덮을 곳** — 평소엔 원작 소리를 낮추고 내레이션. 명대사·반전에서만 내레이션을 멈추고 원작 소리.
4. **콜드 오픈** — 가장 센 장면을 맨 앞에. 제목은 작품명보다 설정으로.
5. **끊기** — 가장 궁금한 지점 직전에서 멈추고 볼 수 있는 곳 안내. 시리즈로 다음 편.

### 2-2. 대본 구조 (`prompts/recap.md`)
콜드 오픈(live 5~8초) → 설정 한 줄(narr) → 발단·갈등·반전·고조(화 순서, 4~6 장면마다 live 하나) → 끊기(`end: true`, 볼 수 있는 곳)

### 2-3. 규칙 (`channel.yaml` 의 `recap_rules`, `recap` 이 검사 — 위반이면 렌더 안 함)
| 규칙 | 값 | 왜 |
|---|---|---|
| 다루는 범위 | 앞 3화까지, 결말 없음 | 본편 대체가 아니라 '보게 만드는' 영상 (시장 대체 여부) |
| 원작 소리 장면 | 하나 ≤ 8초 | 원작을 그대로 들려주는 시간 최소 |
| 원작 소리 합 | ≤ 20% | 나머지 80%는 내 내레이션 (변형성) |
| 마지막 장면 | 궁금한 지점에서 끊고 볼 수 있는 곳 | 시청자를 본편으로 보냄 |
| 음악 | 원작 OST·주제가 안 씀 | Content ID 가 가장 잘 잡는 것 |
| 탐지 회피 | 좌우 반전·확대·테두리·속도/음높이 변조 안 함 | 저장소 규칙(우회 금지) |

> 한국 저작권법 제35조의5·미국 fair use 는 변형성·사용 분량·시장 대체 여부를 본다. 위 규칙은 그 세 가지를 줄이려는 제작 기준이며 법률 자문이 아니다. 저작권 주장이 오면 이의 제기 전에 사용자와 상의.
