## 0. 한 줄 결론

### 1-3. 여기서 얻은 판단
1. **들어갈 자리: A(비교·연출 분석)를 본체로, B(보기 전 총정리)를 시기성 회차로.**
   - A는 같은 규모(2만) 채널이 이미 증명했고, 저작권 구조가 가장 안전하다.
   - B는 방영·개봉 일정에 맞추면 검색 유입이 크다. 다만 줄거리를 길게 틀면 C와 같아지므로 **"원작 설정 + 결말 해석"을 내 화면(관계도·연표) 중심으로** 만든다.
2. **C(전편 몰아보기)는 하지 않는다.** 숫자는 크지만 채널 하나가 경고 3번에 사라지는 구조이고, 저장소 규칙(차단 우회 금지)과도 맞지 않는다.
3. 제목은 **"A vs B"**, **"○○가 좋은 N가지 이유"**, **"보기 전 ○분 총정리"** 가 반복해서 통했다. "왜·이유"만 단독으로 쓴 제목은 배수가 낮았다(0.88) → 질문형은 비교·숫자와 묶는다.

## 2. 채널 설계

| 항목 | 정함 |
|---|---|
| 욕망 | **"본 걸 더 깊이 이해하고 싶다 / 볼지 말지 정하고 싶다"** — 기존 네 브랜드(ai·market·curiosity·issues)와 다른 욕망. 새 브랜드로 둘지 curiosity 아래 라인으로 둘지는 매뉴얼 담당에게 제안 (`proposals/manual/`) |
| 형식 | 롱폼 10~15분(분석) · 30~60분(보기 전 총정리, 분기 1~2편) · 쇼츠(분석 한 장면) |
| 주기 | 주 1편 롱폼 + 같은 소재 쇼츠 2편 |
| 편집 스타일 | `hybrid` 바탕: **원작 클립 ≤8초** + 손그림 관계도·복선 연결선·연표 + 대사 원문(일본어)·번역 2단. 비교 회차는 화면 좌우 맞대기 |
| 목소리 | 3인칭 다큐 내레이터 '~습니다' (v24), 첫 문장부터 질문 |
| 소스 | 사용자가 정식 구독·구매한 에피소드를 PC 에서 준비 (`needs_pc_rebuild: true`). 공식 PV·예고편·키 비주얼 우선 |

### 2-1. 대본 뼈대 (분석 회차)
1. **질문 한 줄** (0~5초): "같은 '울컥하는 대사'인데, 왜 하나는 명대사가 되고 하나는 넘기게 될까요?"
2. **두 장면 맞대기** — 원작 클립 각 5~8초, 바로 내 화면으로.
3. **기준 하나 세우기** — 예: 대사가 '설명'인가 '행동'인가. 손그림 표로.
4. **근거 3개** — 장면마다 클립 짧게 → 도식(카메라 거리·컷 길이·침묵 시간 숫자).
5. **반례 하나** — 기준이 틀리는 경우 (공정함).
6. **다시 보면 달라지는 장면** — 수미상관, 처음 질문에 답.
7. **출처 줄** — 감독·작가 인터뷰, 설정집, 원작 권·화.

### 2-2. 저작권 규칙 (채널 `clip_rules`)
- 원작 클립 1개 ≤ 8초, 영상 전체에서 원작 화면 ≤ 40%.
- 원작 클립 사이에는 반드시 내 화면.
- 원작 OST·주제가는 쓰지 않음 → 무료 음원. 대사 원음은 근거일 때만.
- 좌우 반전·확대·테두리·속도·음높이 변조로 탐지를 피하지 않음.
- 업로드 후 저작권 주장이 오면 이의 제기 전에 사용자와 상의 (자동 대응 안 함).
