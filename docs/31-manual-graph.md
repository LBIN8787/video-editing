# 31. 매뉴얼 그래프 — 영상편집 에이전트의 '정책'을 그래프로

매뉴얼(`manual/`)은 사실상 **영상편집 에이전트의 판단 기준**입니다. 사용자가 영상을 기각하면 기준이 바뀌고(버전이 올라가고),
에이전트는 다음 영상부터 바뀐 기준을 따릅니다. 이 문서는 그 흐름을 **기계가 읽는 그래프**로 만들고, 사람이 보고 고치는 **도구**로 여는 법입니다.
매뉴얼이 정교해질수록 이 그래프가 에이전트의 지식 그래프가 되고, 그 위에 전문 편집 도구를 붙여 나갑니다.

```bash
python -m ytflow manual-graph [--html 보기.html]   # manual/graph.json 다시 만들기 (+ 보기 전용 페이지 한 장)
python -m ytflow manual-ui [--port 8770]           # 브라우저 도구: 그래프 보기 + 매뉴얼 고치기·검토 기록·반영 대기·버전 올리기
python -m ytflow manual-bump "요약"                # 이제 버전을 올리면 graph.json 도 함께 갱신됨
```

원본은 여전히 md 파일입니다(`manual/*.md`, `CHANGELOG.md`, `reviews.md`, `06-checklist.md`, `ytflow/stages/checklist.py`).
`manual/graph.json` 은 언제든 다시 만들 수 있는 파생물이고, 에이전트가 읽기 쉽게 커밋해 둡니다.

## 1. 그래프 모양

| 노드 kind | 무엇 | 어디서 읽나 |
|---|---|---|
| `step` | 한 편을 만드는 8단계 | `manual/README.md` §2 표 |
| `gate` | G0~G8 게이트 | 같은 표 + `06-checklist.md` |
| `channel` | 브랜드(욕망) 4개 | `channels/brands.yaml` |
| `doc` · `section` | 매뉴얼 문서와 절(##·###) | `manual/*.md` 머리말 |
| `rule` | 체크리스트 한 줄 (MUST·SHOULD·EYE, 자동 여부) | `06-checklist.md` 표 |
| `check` | 규칙을 실제로 재는 코드 한 줄 | `ytflow/stages/checklist.py` 의 `R.add(...)` |
| `version` | 매뉴얼 버전 (요약·반영한 기각·커밋) | `CHANGELOG.md` + git |
| `review` | 사용자 검토 (통과·기각, 이유) | `reviews.md` |
| `theme` | 피드백 주제 (움직임·소리·배경·강조·조합·대본·깊이·의도·길이) | 이유 글의 낱말, `manualgraph.THEMES` |

| 엣지 kind | 뜻 |
|---|---|
| `applied_in` | 기각 → 그것을 반영한 버전 (`how`: changelog = 기록으로 확인, inferred = 다음 버전으로 추정) |
| `approved_in` | 통과 → 그때 버전 |
| `touched` | 버전 → 고친 절·문서·게이트 (`via`: changelog 요약의 `03 §0-3`·`G4` 표기 / 절 머리말의 `(vN` / git 커밋에서 바뀐 파일) |
| `gated_by` · `defines` · `belongs_to` · `enforces` | 단계 → 게이트, 06 의 절 → 게이트, 규칙 → 게이트, 검사 코드 → 게이트 |
| `about` · `guided_by` · `contains` | 검토·버전 → 주제, 채널 → 매뉴얼 문서, 문서 → 절 |

## 2. 그래프가 바르게 이어지게 쓰는 법 (매뉴얼을 고칠 때)
- **버전 요약에 고친 곳을 적습니다**: `manual-bump "v32: … (09 §6, README §2-5, check G4)"`. 이 표기로 버전 → 절·게이트가 이어집니다.
- **새 절이나 크게 바꾼 절 머리말에 `(vN, 날짜 사용자: "…")`** 를 붙입니다. 지금도 대부분 이렇게 쓰고 있습니다.
- 기각은 꼭 `review --reject` 로 남깁니다. 그래야 기각 → 버전 연결이 '추정'이 아니라 '확인'이 됩니다.

## 3. 지금 그래프가 보여 주는 것 (v31, 2026-11-15)
- 검토 30건(기각 20 · 통과 10), 기각 20건 모두 반영 버전과 기록으로 이어짐, 반영 대기 0.
- 기각이 가장 많이 겨눈 곳: **스타일 조합·반복 9 · 움직임·카메라 6 · 소리 6** → 화면 연출이 기준 변경의 대부분.
- 규칙 57개 중 49개는 자동 검사. 사람 눈에만 기대는 8개(G2 차단 우회, G3 확인 실패 사실, G6·G7 일부, G8)가 **다음 자동화 후보**.
- 고친 곳이 이어지지 않는 버전: v5·v6·v10·v11·v13·v19 (요약에 `§` 표기가 없음). v29~v31 은 문서(09) 단위까지만 → 위 §2 방식으로 적으면 절까지 이어집니다.

## 4. 에이전트로 넓힐 때 (다음 단계 제안)
1. **단계 시작 전 '이번 단계 규칙 묶음' 조회**: 에이전트가 4단계(대본)에 들어가면 `gate:G4` 에 걸린 rule·check 와, 최근 버전이 고친 절 본문을 그래프에서 뽑아 프롬프트에 넣음.
2. **기각 → 고칠 절 추천**: 새 기각 이유의 주제(theme)와 같은 주제를 겨눴던 과거 버전이 고친 절을 후보로 제시 → 사람이 `manual-ui` 에서 고침.
3. **규칙 ID 고정**: 지금 rule ID 는 표 순서(`rule:G4:3`)라 줄이 바뀌면 바뀜. 에이전트가 규칙을 참조하기 시작하면 06 표에 고정 ID 열을 추가.
4. **EYE → 자동**: 사람 눈 규칙 8개를 `checklist.py` 검사로 바꾸면 `enforces` 엣지가 생겨 그래프에서 덮인 정도가 바로 보임.
5. **영상 결과와 잇기**: 프로젝트의 `checklist.json`·`sync_qa.json`·`layout_qa.json` 을 review 노드에 붙이면 '어떤 측정값일 때 기각됐나'를 학습 자료로 쓸 수 있음.

## 5. 도구 (`manual-ui`)
- **피드백 → 매뉴얼**: 검토(왼쪽) → 반영 버전(가운데) → 고친 절·게이트(오른쪽). 누르면 그 경로만 남음.
- **매뉴얼 구조**: 8단계 카드(규칙 MUST·SHOULD·EYE 비율, 검사 코드 수)와 문서·절 목록(마지막으로 바꾼 버전, 진할수록 최근).
- **버전 타임라인**: 가로 버전 × 세로 피드백 주제. 기각 점은 반영된 버전에, 통과 점은 통과한 버전에.
- **고치기·제어**: 검토 기록 / 반영 대기 추가·빼기 / 버전 올리기 / `manual/*.md` 직접 편집(저장하면 그래프 즉시 갱신) / 버전별 바뀐 내용(git diff).
- 서버는 `127.0.0.1` 에만 열고, `manual/*.md` 밖의 파일은 읽거나 쓰지 않습니다. 커밋·push 는 사람이 합니다(버전을 올리면 화면에 명령이 나옵니다).
- `--html` 로 만든 페이지는 읽기 전용입니다. 편집 칸에는 같은 일을 하는 명령이 나와 복사해 씁니다.
