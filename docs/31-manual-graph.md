# 31. 매뉴얼 그래프 — 영상편집 에이전트의 '정책'을 그래프로

매뉴얼(`manual/`)은 사실상 **영상편집 에이전트의 판단 기준**입니다. 사용자가 영상을 기각하면 기준이 바뀌고(버전이 올라가고),
에이전트는 다음 영상부터 바뀐 기준을 따릅니다. 이 문서는 그 흐름을 **기계가 읽는 그래프**로 만들고, 사람이 보고 고치는 **도구**로 여는 법입니다.
매뉴얼이 정교해질수록 이 그래프가 에이전트의 지식 그래프가 되고, 그 위에 전문 편집 도구를 붙여 나갑니다.

```bash
python -m ytflow manual-graph [--html 보기.html]   # manual/graph.json 다시 만들기 (+ 보기 전용 페이지 한 장)
python -m ytflow manual-ui [--port 8770]           # 브라우저 도구: 그래프 보기 + 매뉴얼 고치기·검토 기록·반영 대기·버전 올리기
python -m ytflow manual-bump "요약"                # 이제 버전을 올리면 graph.json 도 함께 갱신됨
```

원본은 여전히 md 파일입니다(`manual/*.md`, `CHANGELOG.md`, `reviews.md`, `06-checklist.md`, `ytflow/stages/checklist.py`).
`manual/graph.json` 은 언제든 다시 만들 수 있는 파생물이고, 에이전트가 읽기 쉽게 커밋해 둡니다.

## 1. 그래프 모양

| 노드 kind | 무엇 | 어디서 읽나 |
|---|---|---|
| `step` | 한 편을 만드는 8단계 | `manual/README.md` §2 표 |
| `gate` | G0~G8 게이트 | 같은 표 + `06-checklist.md` |
| `channel` | 브랜드(욕망) 4개 | `channels/brands.yaml` |
| `doc` · `section` | 매뉴얼 문서와 절(##·###) | `manual/*.md` 머리말 |
| `rule` | 체크리스트 한 줄 (MUST·SHOULD·EYE, 자동 여부) | `06-checklist.md` 표 |
| `check` | 규칙을 실제로 재는 코드 한 줄 | `ytflow/stages/checklist.py` 의 `R.add(...)` |
| `version` | 매뉴얼 버전 (요약·반영한 기각·커밋) | `CHANGELOG.md` + git |
| `review` | 사용자 검토 (통과·기각, 이유) | `reviews.md` |
| `theme` | 피드백 주제 (움직임·소리·배경·강조·조합·대본·깊이·의도·길이) | 이유 글의 낱말, `manualgraph.THEMES` |

| 엣지 kind | 뜻 |
|---|---|
| `applied_in` | 기각 → 그것을 반영한 버전 (`how`: changelog = 기록으로 확인, inferred = 다음 버전으로 추정) |
| `approved_in` | 통과 → 그때 버전 |
| `touched` | 버전 → 고친 절·문서·게이트 (`via`: changelog 요약의 `03 §0-3`·`G4` 표기 / 절 머리말의 `(vN` / git 커밋에서 바뀐 파일) |
| `gated_by` · `defines` · `belongs_to` · `enforces` | 단계 → 게이트, 06 의 절 → 게이트, 규칙 → 게이트, 검사 코드 → 게이트 |
| `about` · `guided_by` · `contains` | 검토·버전 → 주제, 채널 → 매뉴얼 문서, 문서 → 절 |

## 2. 그래프가 바르게 이어지게 쓰는 법 (매뉴얼을 고칠 때)
- **버전 요약에 고친 곳을 적습니다**: `manual-bump "v34: … (09 §6, README §2-5, check G4)"`. 이 표기로 버전 → 절·게이트가 이어집니다.
- **새 절이나 크게 바꾼 절 머리말에 `(vN, 날짜 사용자: "…")`** 를 붙입니다. 지금도 대부분 이렇게 쓰고 있습니다.
- 기각은 꼭 `review --reject` 로 남깁니다. 그래야 기각 → 버전 연결이 '추정'이 아니라 '확인'이 됩니다.

## 4. 에이전트로 넓힐 때 (다음 단계 제안)
1. **단계 시작 전 '이번 단계 규칙 묶음' 조회**: 에이전트가 4단계(대본)에 들어가면 `gate:G4` 에 걸린 rule·check 와, 최근 버전이 고친 절 본문을 그래프에서 뽑아 프롬프트에 넣음.
2. **기각 → 고칠 절 추천**: 새 기각 이유의 주제(theme)와 같은 주제를 겨눴던 과거 버전이 고친 절을 후보로 제시 → 사람이 `manual-ui` 에서 고침.
3. **규칙 ID 고정**: 지금 rule ID 는 표 순서(`rule:G4:3`)라 줄이 바뀌면 바뀜. 에이전트가 규칙을 참조하기 시작하면 06 표에 고정 ID 열을 추가.
4. **EYE → 자동**: 사람 눈 규칙 8개를 `checklist.py` 검사로 바꾸면 `enforces` 엣지가 생겨 그래프에서 덮인 정도가 바로 보임.
5. **영상 결과와 잇기**: 프로젝트의 `checklist.json`·`sync_qa.json`·`layout_qa.json` 을 review 노드에 붙이면 '어떤 측정값일 때 기각됐나'를 학습 자료로 쓸 수 있음.

## 5. 도구 (`manual-ui`)
- **피드백 → 매뉴얼**: 검토(왼쪽) → 반영 버전(가운데) → 고친 절·게이트(오른쪽). 누르면 그 경로만 남음.
- **매뉴얼 구조**: 8단계 카드(규칙 MUST·SHOULD·EYE 비율, 검사 코드 수)와 문서·절 목록(마지막으로 바꾼 버전, 진할수록 최근).
- **버전 타임라인**: 가로 버전 × 세로 피드백 주제. 기각 점은 반영된 버전에, 통과 점은 통과한 버전에.
- **고치기·제어**: 검토 기록 / 반영 대기 추가·빼기 / 버전 올리기 / `manual/*.md` 직접 편집(저장하면 그래프 즉시 갱신) / 버전별 바뀐 내용(git diff).
- 서버는 `127.0.0.1` 에만 열고, `manual/*.md` 밖의 파일은 읽거나 쓰지 않습니다. 커밋·push 는 사람이 합니다(버전을 올리면 화면에 명령이 나옵니다).
- `--html` 로 만든 페이지는 읽기 전용입니다. 편집 칸에는 같은 일을 하는 명령이 나와 복사해 씁니다.

## 6. 의도 정렬 — 내가 한 말과 모델의 해석이 맞는지 (`manual-ui` 첫 탭)

매뉴얼은 사용자의 말을 모델이 **해석해서** 적은 것입니다. 해석이 지나치거나(과잉), 덜하거나, 다른 뜻으로 옮겨지면
매뉴얼이 정교해질수록 오히려 엇나간 방향으로 굳습니다. 예: "동영상의 이점을 살려라(다음 PPT, 다음 PPT 가 아니라)"를
v25 가 **"카메라가 계속 움직인다 · 완전히 멈춘 순간이 없게 · 정지 비율 ≤0.3 MUST"** 로 옮겼고, 그 뒤 v30·v31 에서
"억지로 웅웅거리지 마라 · 확대·축소 쓰지 마라"로 되돌아왔습니다. 당시(v31) 매뉴얼에는 두 방향이 함께 살아 있었습니다 (v34 에서 정리)
(README §2-5·05 §0-4 '계속 움직임' ↔ 09 §6·04 §0-5·05 §0-5 '끔·고정이 기본').

### 사슬
| 고리 | 무엇 | 자동으로 찾는 법 |
|---|---|---|
| ① 사용자 원문 | 사용자가 실제로 한 말 | `reviews.md` 기각 이유 · 매뉴얼 머리말·본문의 `사용자: "…"` · 코드 주석의 `사용자: "…"` (비슷한 원문은 하나로 묶음) |
| ② 모델 해석 | 그 말을 옮긴 버전 요약 | 원문 옆 `vN`, 검토 → 반영 버전 |
| ③ 매뉴얼 규칙 | 그 버전이 고친 절 | §1 의 `touched` |
| ④ 코드·검사 | 그 버전을 구현한 코드 | `ytflow/**/*.py` 의 `# vN …` 주석, 검사 이름의 `vN:` |
| ⑤ 결과 | 그 뒤 같은 주제의 검토 | `reviews.md` (날짜·버전·주제) |

### 판정 (`manual/intents.yaml`, 사람이 고치는 원본)
- 의도마다 **뜻한 것**(`meaning`)과 **뜻하지 않은 것**(`not_meant`)을 적고, ③④의 해석마다 상태를 고릅니다:
  `aligned` 정렬됨 · `over` 과잉 해석 · `under` 덜 반영 · `drift` 다른 뜻으로 · `conflict` 다른 규칙과 충돌 · `unreviewed` 미검토.
- **반영 대기로 보내기**를 누르면 어긋난 해석이 `CHANGELOG.md` '반영 대기'에 들어가고, 고칠 때까지 `check` G0 가 실패합니다
  → 기존 기각 → 버전 루프를 그대로 탑니다.
- 에이전트는 `manual/graph.json` 의 intent 노드(원문·뜻한 것·뜻하지 않은 것·판정)를 규칙과 함께 읽습니다 — 규칙 글자보다 **원래 뜻**을 먼저 봅니다.
- **충돌 후보**: 지금 매뉴얼에서 같은 주제를 '더 하라'(계속·끊임없이·반드시)와 '덜 하라'(끈다·쓰지 않음·고정이 기본)로 말하는 줄을 자동으로 짝지음. 낱말로 추정한 것이라 채널 범위가 다르면 충돌이 아닐 수 있습니다.
- 코드 해석은 `code:파일:줄` 로 가리켜서 코드 줄이 옮겨지면 판정이 '위치 바뀜'으로 남습니다 → 화면에서 새 줄에 다시 판정하세요.

## 7. 한눈에 · 작업 절차 · 내 피드백 → 매뉴얼 · 용어 사전 (2026-11-15 사용자 요청)

> "그래서 저게 뭐야?" 싶은 말을 누르면 무슨 스타일이고 어떻게 구현됐는지 알 수 있게 · 뭐가 통과이고 뭐가 금지이고 뭐가 충돌 후보인지 보이게 · 작업 절차를 한눈에 · 내 피드백이 어떻게 매뉴얼이 됐는지.

| 탭 | 보이는 것 |
|---|---|
| **한눈에** (첫 화면) | 충돌 후보(▲ 더 하라 ↔ ▼ 덜 하라·끈다) · 어긋난 의도 · 금지·하지 않는 것(절대 금지 / 주제별) · 통과한 영상과 검증된 버전 · 기각한 영상 → 반영 버전. 위 숫자 칸을 누르면 그 목록으로 감 |
| **작업 절차** | README §2·§5 그대로의 흐름도: 요청 → 1~8단계(G1~G8) → 대본 먼저 검토(호기심) → check → 내 검토 → 통과 / 기각 → 반영 대기 → 의도 확인 → 매뉴얼·코드 고치기 → 버전 올리기 → 다음 영상. 빨간 숫자 = 그 단계를 바꾼 내 기각 수. 누르면 하는 일·명령·통과 규칙·바꾼 피드백 |
| **내 피드백 → 매뉴얼** | 기각 하나마다 카드: 내 말 → 모델이 옮긴 버전 → 바뀐 절·게이트 → 코드 → 의도 판정 → 그 뒤 같은 영상 결과. '연결 그림으로 보기'는 예전 3단 연결 그림 |
| **용어 사전** | 편집 스타일(styles/recipes) · 장면 종류(렌더 함수 RENDER) · 시각 효과(directions.FX) · 그래픽 팩(skins) · 움직임·측정 용어(`manual/glossary.yaml`). 원리 움직임 예시 · 무엇인가 · 화면에서 · 헷갈리기 쉬운 점 · 어떻게 만들어지나(파일:줄) · 켜고 끄는 법 · 매뉴얼·코드에서 나오는 곳 |

- 모든 화면에서 **점선 밑줄 친 말**(스타일·장면·효과·움직임)을 누르면 용어 카드가 열립니다. 휴대폰에서는 아래에서 올라오는 창, '← 뒤로'로 앞 화면.
- 코드에 이름이 없는 말(박자 카메라·대기 동작·원근 종이·정지 화면 비율 등)은 `manual/glossary.yaml` 에 사람이 씁니다. `code: ["파일::그 줄의 글자"]` 로 적으면 줄 번호가 바뀌어도 그래프가 지금 줄을 찾습니다. 같은 key 로 적으면 자동 설명을 덮어씁니다.
- '금지'는 지금 매뉴얼에서 금지·쓰지 않·하지 않·끈다 같은 말이 든 줄을 모은 것(README §3 '절대 하지 않는 것'은 따로 표시). 충돌 후보처럼 낱말로 모은 것이라 문맥은 원문으로 확인합니다.
- 움직임 예시는 실제 렌더 화면이 아니라 원리를 보여 주는 작은 그림입니다.

## 8. 피드백하면 그래프도 함께 (2026-11-15 사용자: "앞으로 제가 피드백하면 해당 그래프도 업데이트 할 수 있도록")

| 사용자가 한 것 | 기록 (원문 그대로) | 그래프 |
|---|---|---|
| 영상 통과·기각 | `python -m ytflow review <프로젝트> --pass \| --reject "원문"` → `reviews.md`·반영 대기 | 자동으로 다시 만듦 |
| 방향·기준 요청 ("인트로 빼 주세요") | `python -m ytflow feedback "원문" --kind direction [--pending]` → `manual/feedback.yaml` | 자동 · 새 사용자 원문(의도)으로 들어감 |
| 뜻 바로잡기 ("그런 뜻이 아니었다") | `feedback "원문" --kind clarify --about intent:xxxx` + `intents.yaml` 판정 | 자동 · 그 의도에 '내가 바로잡은 말'로 붙음 |
| 매뉴얼을 고침 · 버전 올림 | `manual-bump` · `manual-ui` 저장 | 자동 |

- `manual-ui` '고치기·제어'의 **0. 내 말 기록** 칸에서도 같은 일을 합니다. '한눈에' 맨 위 **내 피드백** 목록에 날짜 순으로 나오고, 각 말이 어디로 갔는지(반영 버전 · 반영 대기 · 바로잡은 의도) 보입니다.
- **공유 페이지**(읽기 전용, `ARTIFACT_URL`)는 에이전트가 다시 올립니다: `python -m ytflow manual-graph --artifact <스크래치>/manual-graph.html` → Artifact 도구로 같은 주소에 publish(다른 세션이면 `url` 지정) → 커밋·push.
- 잊으면: `graph.json` 의 `source_hash` 가 매뉴얼·검토·피드백·판정·용어 파일의 지문과 다르면 `check` G0 SHOULD "매뉴얼 그래프가 최신" 이 실패합니다.

## 9. 규칙의 네 층 · 과적합 후보 (2026-11-15 사용자: "영구적인 매뉴얼 작업지침과 일시적인 스타일 변화·다양한 방법 모색에서 생기는 피드백이 과적합해서 하지 말아야 할 것에 들어가는 것 같다 — 구분해 달라")

- 금지 줄(매뉴얼에서 '금지·쓰지 않·하지 않·끈다'가 든 줄) · 체크리스트 규칙(06) · 검사 코드(`R.add`) · 검토 · 피드백마다 **층**을 붙입니다: 영구 원칙 · 작업 기준 · 스타일 기본값 · 실험 기록 (`manual/README.md` §3-1).
- **자동 추정** (`manualgraph.classify`): README §3 이거나 사실·법·권리·안전 낱말 → 영구 원칙 / 소리·카메라·바탕·스타일 비율 낱말 → 스타일 기본값, 그중 금지·MUST 인데 근거 버전이 반영한 영상이 한 편뿐이면 → 실험 기록 / 나머지 → 작업 기준.
- **과적합 후보** = 스타일·실험 층인데 금지·MUST 로 적힌 것 (사람이 스타일로 확정하면 후보에서 빠짐, 실험으로 확정했는데 금지로 적혀 있으면 계속 후보). '한눈에' 맨 위.
- **사람이 확정**: `manual-ui` '한눈에'의 줄마다 층 선택 → `manual/rule_tiers.yaml` (key 는 그 줄 글자에서 만들어져, 글을 고치면 자동 추정으로 돌아감). 2026-11-15 Claude 제안 18줄이 들어 있음(`by: Claude 제안 — 사용자 확인 필요`).
- 피드백을 기록할 때 층을 정함: `python -m ytflow feedback "원문" --scope principle|standard|style|trial` ('내 말 기록' 칸의 '이 말의 층').
- 매뉴얼 글 자체(금지 문장을 기본값 문장으로, 스타일 MUST 검사를 SHOULD 로)는 사용자가 층을 확인한 뒤 버전을 올려 고칩니다.
