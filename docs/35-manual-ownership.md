# 35. 매뉴얼은 한 번에 한 명만 — 고칠 때만 잠그고 순서대로 (2026-11-15, 2026-11-16 바꿈)

> 2026-11-15 사용자: "매뉴얼 작성을 이 에이전트 저 에이전트 중복해서 수정하지 않도록 깃 수정 등 파일관리는 한번에 한명만 하도록 하세요. 여기저기 뒤죽박죽 하지 말고 관리하자는 거예요."
> 2026-11-16 사용자: "담당 세션이 하는게 아니라 그냥 순차적으로 서로 메뉴얼 관리할때만 잠금하고 잠금도중에 누군가 사용하려하면 그냥 요청하면 되는거 아니야?" · "바뀐 메뉴얼을 바탕으로 또 다음메뉴얼이 작성되기도 하는데 지금은 텀이 너무 길잖아"
> 결정 변화: 처음엔 **담당 1명 + 26시간 잠금** → 다른 세션의 반영이 다음 밤까지 밀림 → **정해진 담당 없이, 고칠 때만 짧게 잠그고 순서대로**.
> 보호 범위(매뉴얼과 규칙 파일)·막는 장치 세 겹은 그대로.

## 순서 (누구든 같음)
```
manual-lock acquire --purpose "…"   ← 비어 있거나 만료됐으면 누구나. 잡자마자 main 을 이 브랜치에 합침(앞 사람이 고친 것 위에서 시작)
  고치기 (feedback·review·manual-bump·매뉴얼 수정)
  push → PR → main 에 합치기          ← 다음 사람이 바로 이 결과 위에서 시작
manual-lock release                 ← main 에 안 합친 매뉴얼 변경이 있으면 거절 (--anyway 로만 강제)
```
- 유효 시간 **2시간** (`manual/OWNERS.yaml` `lock.hours`). 길어지면 `acquire` 다시 = 연장. 세션이 끊겨도 2시간 뒤 저절로 풀림.
- 이전처럼 한 세션이 하루 종일 쥐고 있지 않는다. 매일 밤 정기 검토(docs/34)도 그냥 한 작업 — 잡고, 고치고, 합치고, 푼다.

## 잠겨 있을 때
- `python -m ytflow manual-lock request "내용"` → 요청이 `proposals/manual/` 에 `kind: request` 로 남음 (파일 하나 = 요청 하나, 병렬로 써도 충돌 없음).
- 잡고 있는 세션은 `status`·`acquire`·`release` 때 기다리는 요청을 본다 — 할 수 있으면 같이 처리.
- 아니면 풀린 뒤(release·만료) 요청한 세션이 직접 `acquire` 해서 처리. 급하지 않은 것은 `manual-propose` 로 남겨 다음 사람·정기 검토가 반영.
- 사용자가 지금 잡고 있는 쪽을 비키게 하면: `acquire --force --reason "사용자 허락: …"` (넘겨받은 기록이 잠금에 남음).

## 잠금 장치
- 잠금은 원격 브랜치 **`locks`** 의 `manual-lock.json` 한 파일. 그 파일만 바꾼 커밋을 push 해서 잡고 푼다 — 둘이 동시에 잡으면 늦은 쪽 push 가 거절되고, 쓰기 직전에도 원격 잠금을 다시 확인한다.
- `locks` 브랜치에 잠금 커밋을 올리는 것은 사용자가 허락함 (2026-11-15). 잠금 파일 말고는 아무것도 올리지 않는다.

## 막는 장치 (세 겹)
1. **명령**: 잠금이 비어 있으면 `review`·`feedback`·`manual-bump`·`manual-ui` 저장이 그 자리에서 짧게 잡고(`auto_hours`) 씀. 다른 사람이 잡고 있을 때만 멈추고 요청·제안함으로 (2026-11-18, 아래). `manual-graph`·`manual-audit` 은 잠금이 없으면 보기만.
2. **Claude Code hook** (`.claude/settings.json` PreToolUse): 보호 파일을 Edit·Write 하려 하면 잠금을 확인하고, 없으면 이유와 함께 막음. 세션이 시작될 때 잠금 상태를 보여 주고 git hook 을 켬.
3. **git pre-commit** (`.githooks/pre-commit`, `git config core.hooksPath .githooks`): 보호 파일이 든 커밋을 잠금 없이 하면 거절. Codex 등 다른 에이전트도 이 hook 과 AGENTS.md 규칙을 따른다.
급히 혼자 쓸 때만 `YTFLOW_MANUAL_GUARD=off` (사용자가 직접 할 때).

## main 에 반영
잠금을 가진 세션은 자기 매뉴얼 PR 을 main 에 합칠 수 있다 (사용자 허락 2026-11-15). 충돌이 나면 양쪽 내용을 살려 풀고, 서로 반대면 합치지 말고 사용자에게 묻는다. 매뉴얼 버전 번호는 main 의 최신 다음 번호 (acquire 때 main 을 합치므로 겹치지 않음). `manual/vN` 스냅샷 브랜치는 덮어쓰지 않는다.

## 보호 범위 바꾸기
`manual/OWNERS.yaml` 의 `protected`·`open`. 저장소 전체를 한 명만 고치게 하려면 `protected` 에 `"**"` — 단, 매일 아침 시장 브리핑·30분마다 오는 SAVE 알림 커밋도 잠금을 기다리게 되어 병목이 생긴다.

- 적용: `review`, `feedback`, `manual-bump`, Claude 편집 hook, git pre-commit.
