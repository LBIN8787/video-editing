## 2. 이 영상이 잘하는 점 (왜 볼 만한가)
1. **한 문장 = 한 상태 변화.** 카드가 '대기 → 진행 → 성공/실패'로 바뀌어, 소리를 꺼도 사건 순서가 읽힙니다.
2. **증거 → 재연 짝.** 기사 캡처로 사실을 박고, 곧바로 마스코트 재연으로 뜻을 풉니다. 둘이 번갈아 나와 지루함과 신뢰를 함께 잡습니다.
3. **색 하나로 판정.** 라임 = 된다/강조, 빨강 = 안 된다/위험. 이 두 색만 보고도 좋은 일·나쁜 일이 구분됩니다.
4. **사람 대신 마스코트.** AI 의 행동 주체를 하나의 캐릭터로 고정해, 여러 사례가 '같은 주인공의 이야기'로 묶입니다.
5. **표지는 꼭 필요한 곳에만.** 문제 4꼭지에만 표지를 써서 구조가 분명합니다.

약점·주의: 마스코트는 상업 제품의 캐릭터와 비슷한 모양이라 우리가 쓰면 해당 제품을 연상시킬 수 있음 / 기사 캡처가 길게 머물 때(6~9초) 화면 변화가 형광펜뿐이라 느려짐 / 재연 목업은 실제 화면이 아님 — 고지를 반드시 붙여야 함.

- **호기심 채널:** A8 비유 오브젝트·공간 배치 정도만. 이야기형은 기존 그림판·애니메이션 무대가 맞음.

## 4. 우리 엔진에 없는 것 (구현 후보)
1. **카드 상태 전이** — 같은 카드가 대기 → 진행(점 세 개·펄스) → 성공(✓)·실패(빨간 테두리+X)로 바뀌는 장면 하나. 박자마다 `state` 만 바꾸면 되게.
2. **선 상태 바꾸기** — 그려진 연결선을 지우지 않고 빨간 점선으로 바꾸는 효과(인과 지도에 바로 붙일 수 있음).
3. **실사 위 칩 떠오르기** — 실사 영상 위에 말 칩을 0.6초 간격으로 하나씩.
4. **기사 캡처 스포트라이트** — 나머지 본문을 어둡게 깔고 한 줄만 밝게(형광펜과 함께).
5. **두 줄 장 표지** — 어두운 실사 + 작은 줄 → 큰 강조색 줄.
6. **모양 매치 아이리스** — 앞 장면 원을 키워 전환.

→ §6 에서 구현했고, v50(2026-11-19)에서 매뉴얼·`styles/techniques.yaml` 에 반영했습니다.

## 6. 구현 (2026-11-18) — `ytflow/stages/uiflow.py`
§4 의 여섯 가지를 하이브리드 렌더러(`python -m ytflow hybrid`)에 넣었습니다. 기존 장면은 그대로이고, 아래 키를 쓸 때만 켜집니다.

| # | 기법 | 대본(02_script/hybrid.json)에 쓰는 법 |
|---|---|---|
| 1 | 카드 상태 바꾸기 | 장면 `"type": "statecard"`, `cards: [{id, label, icon, sub}]`(최대 6), 선택 `hub: {label, icon}`(가운데 주체 + 연결선). 박자마다 `show: [id…] \| "all"`, `state: {id: "wait"\|"run"\|"ok"\|"fail"}`, `text: {id: "바뀐 작은 줄"}`. 좌상단 `*이해를 돕기 위한 연출입니다` 가 기본으로 붙음(`notice: false` 로 끔, 문자열로 바꿈) |
| 2 | 선 → 빨간 점선 + X | statecard 박자 `cut: [id…]`(hub 선이 끊기고 카드는 실패 상태) · 인과 지도 `map_causal` 박자 `cut: [["a","b"]]`(그려 둔 화살표가 흐려지고 빨간 점선 + X) |
| 3 | 실사 위 말 칩 | `footage` 박자 `chips: ["…", {"text": "…", "x": 600, "y": 300, "color": "#…"}]`, 간격 `chip_gap`(기본 0.6초), 최대 6개 |
| 4 | 기사 스포트라이트 + 형광펜 + 숫자 카드 | 장면 `"type": "docspot"`, `source`(꼬리표), `headline`, `paras: [문단…]` — 또는 캡처 그림 `img: "footage/x.png"`. 박자 `spot: 문단 번호 \| [번호…]`(그림이면 `[x, y, w, h]` 비율), `mark: false` 로 형광펜 끔, `spot: null` 로 막 걷기, `num: {value, label, sub}` 옆 숫자 카드(세어 올라감 + 밑줄 바) |
| 5 | 두 줄 장 표지 | `chapter` 장면에 `"look": "two-line"`, `kicker`(작은 흰 줄), `title`(큰 강조색 줄), 바탕은 `clip`(실사) 또는 장면 바탕 위 어두운 막(`dim`, 기본 0.62). 색 `color` / `lime: true` |
| 6 | 모양 매치 아이리스 | 앞 장면에 `"iris_out": {"x": 960, "y": 540, "r": 130}`(그 장면의 원 모양 위치·반지름) → 원 테두리가 커지며 화면을 덮고, 다음 장면이 같은 색에서 원으로 열림. `color`(기본: 영상 팩 바탕색), `to: [x, y]`(다음 장면이 열리는 중심) |

**시험 렌더:** 다섯 장면(32.8초) 시험 프로젝트를 렌더해 프레임으로 확인 — 상태 배지(진행 ••• → ✓ / ✕), hub 선 끊김, 인과 지도 화살표 끊김, 문단 스포트라이트 이동·형광펜·숫자 카운트업, 두 줄 표지, 칩 3개, 아이리스 이어짐. sync-qa 통과.
**남은 점:** docspot 의 어둡게 깐 문단은 일부러 대비를 낮춘 것이라 레이아웃 점검(contrast)에 경고가 남습니다. 매뉴얼·기법 카탈로그에는 v50(2026-11-19)로 반영했습니다. 스킬 등록은 하지 않았습니다. 아이리스는 바탕색을 거쳐 열리며 다음 장면을 원 안에 직접 합성하지 않습니다.
