# 66. 방송·대형 제작 팀의 연출은 어떻게 정해지나 — 사례 조사와 '연출 결정 기록' (2026-11-24)

> 사용자: "더 이런 편집사례들을 조사하세요. 제가 원하는건 방송국이나 대형 인력들이 만드는 편집연출정도의 레벨입니다. 또한 단순 다큐를 사용할때만 이를 작성하는 것이 아니라 선택과 방향성 설정에 있어서 이를 기록하라는 것 입니다. 다양한 연출법 편집법 스타일들이 존재하는데 그 다양한 것들 중 이것을 선택한 근거와 의도가 명확해야합니다. 제가 주의하는건 추적 불가능하고 일관성이 없는 단순 슬롭입니다."
>
> 이 문서: ① 방송·대형 팀 사례에서 '품질을 만드는 것'이 무엇인지 ② 우리 영상이 지금 어디서 슬롭이 되는지(측정) ③ 그래서 만든 장치 — 연출 결정 기록(`decide`).
> 확인 수준: ✅ 원문·공식 페이지 / 🔎 검색 요약(2차) / ❔ 못 찾음(직접 보고 확인 필요). 대사·그림·로고는 가져오지 않습니다 — 구조와 방법만.

### 방송·대형 팀의 공통점 — 품질은 '움직임'보다 '결정'에서 나온다
1. **먼저 정하고 잠근다 (B7·B11).** 무엇을 어떤 그림으로 보여 줄지(은유·장면 종류)는 스토리보드 단계에서, 색·글꼴·그림체는 스타일 프레임에서 정해 승인받은 뒤 애니메이션을 시작한다. 만들면서 고르지 않는다.
2. **한 편 = 시각 언어 하나 (B3·B4·B1).** 요소 목록(체계)을 세우고 그 안에서 겹치고 다시 섞는다. 장면마다 새 스타일을 꺼내지 않는다 — 그래서 일관되고, 시청자가 그림 읽는 법을 한 번만 배운다.
3. **움직임은 이야기에 봉사 (B7·B8).** 내레이션 타이밍이 움직임을 이끌고, 은유는 대본의 동사에서 나온다.
4. **근거를 화면에 (B6).** 그래픽이 근거를 대신하지 않고, 원본(문서·영상)을 보여 주며 짚는다.
5. **사람이 많아서가 아니라 단계마다 책임이 나뉘어서 (B4·B5).** 누가 무엇을 왜 정했는지가 남는다 — 우리는 사람 대신 **기록**으로 이것을 한다.

## 2. 우리는 지금 어디서 슬롭이 되나 (측정, 2026-11-24)
최근 18편(`projects/202611{11..24}-*`)에서 실제 장면과 `edit-plan` 추천·`style-pick` 추천을 비교:

| 측정 | 결과 |
|---|---|
| 장면 종류가 edit-plan 추천과 다른 비율 | 편마다 46~76%, 평균 약 65% |
| 같은 상황인데 다른 장면을 쓴 상황 수 | 편마다 1~5개 |
| 왜 그렇게 골랐는지 적힌 장면 | **0개** (호기심 11-13 한 편만 14개 — stage 장면의 goal/why) |
| 예: 20261124 시장 | style-pick 1순위는 `issue-dark-montage`(어두운 몽타주·지도)인데 실제는 대결·막대·체크리스트·설명 무대. 바꾼 이유 기록 없음 |

- 추천과 다른 것이 곧 잘못은 아닙니다. **추천 쪽이 틀린 경우도 많습니다** — edit-plan 은 낱말 신호로 상황을 찾아서 '%·달러'가 들어간 박자를 거의 다 `metric`(숫자)으로 읽습니다(20261124 에서 13장면 중 8장면).
- 문제는 **어느 쪽이 맞았는지 아무도 모른다**는 것: 기록이 없으니 다음 영상이 같은 판단을 다시 하고, 추천기도 고쳐지지 않고, 사용자가 '왜 이 장면이 이렇게 생겼나'를 물어도 답이 없습니다. 이것이 추적 불가능·일관성 없는 슬롭입니다.

## 3. 연출 결정 기록 (`decide`) — 방송의 트리트먼트·스토리보드 승인을 기록으로
렌더 전에 두 층으로 적고, 검사가 통과해야 렌더합니다(manual/05 §0-8).

**영상 방향 (hybrid.json `direction`, 한 번):** 고른 시각 언어(`pick`) · 고려했다 버린 스타일과 이유(`over[].why_not`, style-pick 후보에서) · 왜(`why`: 질문·소스·시청자) · 의도(`intent`) · **이 영상의 장면 어휘**(`vocabulary`: 닫힌 목록, B2·B3) · 근거 문서(`refs`).

**장면마다 (`decide`):** 상황(`situation`, 등록된 id) · 고른 장면(`pick` = 실제 type) · 버린 대안과 이유(`over`) · 왜(`why`) · 의도(`intent`: 이 장면이 끝나면 시청자는 …) · 근거(`refs`) · 같은 상황인데 다른 장면이면 `differs` · 어휘 밖이면 `new_vocab`.

| 검사 (`python -m ytflow decide <프로젝트>`) | 막는 슬롭 |
|---|---|
| 기록한 pick = 실제 장면 type | 기록과 화면이 따로 노는 것 (추적 불가) |
| situation 이 등록된 상황 · refs 가 실제 파일·기법·스타일 | 출처 없는 이유, 지어낸 근거 |
| why·intent·over(대안+버린 이유) 필수, 다른 장면의 why 복사 금지 | '그냥', 이유 돌려쓰기 |
| edit-plan 1순위와 다르면 over 에 1순위와 버린 이유 | 추천을 말없이 무시 (추천이 틀렸으면 그것도 기록 → 추천기 개선 자료) |
| 같은 상황 → 같은 장면, 다르면 differs | 장면마다 기분 따라 다른 화면 |
| vocabulary 밖이면 new_vocab | 한 편 안에서 스타일이 계속 늘어나는 것 |
| 다큐 장면(`docu`)은 큰 움직임마다 why (docs/65 §8) | 화려해 보이려는 움직임 |

산출물: `02_script/DIRECTION_LOG.md`(사람이 렌더 전에 한 장으로 검토) · `direction_log.json`. `--draft` 는 edit-plan 추천으로 뼈대를 채우고 이유 자리를 TODO 로 둡니다(채우기 전엔 실패).

### 예시 — 20261124 시장(다큐 시범본)에 직접 적용
- 방향: 「어두운 데이터 무대 + 개념 설명 한 곳만 docu」. 버린 것: `issue-dark-montage`(증거가 공시·종가라 보여 줄 현장 사진·지도가 없음 → 몽타주는 장식), `map-journey`(사슬은 지리 이동이 아니라 거래 관계), `archive-doc`(훅 자료 화면 없음).
- 검사가 처음에 잡은 것 4개(제 기록에서도): 같은 '숫자' 상황인데 2번 막대·5번 큰 숫자(→ differs: 여럿 비교 vs 계산 하나), 8번 docu 가 추천 1순위 bignum 을 말없이 버림(→ 추천기가 '%'만 보고 metric 으로 오판 — 기록), 같은 '결론' 자리인데 17번 목록·18번 키네틱(→ differs: 틀릴 조건 목록 vs 결론 한 문장).
- 결과 파일: `E:\ytflow-local\docu-pilot\20261124-market-daily\02_script\DIRECTION_LOG.md`

### 적용 범위
- 2026-11-25 이후 만드는 영상부터 MUST(G5). 그 전 영상은 참고로만(기록이 없던 시절).
- 매일 영상(시장 브리핑)도 같습니다 — 같은 형식이 반복되면 `direction` 은 전날 것을 그대로 쓰되, 바꾸는 곳에만 새 이유를 적습니다(바꾸지 않은 이유를 매일 새로 지어내지 않음).
