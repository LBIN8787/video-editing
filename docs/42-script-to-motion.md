# 대본에서 화풍과 움직임을 고르는 법

이 절차는 사람이 그린 원화, 기존 삽화, 생성 원화를 모두 받는다. 기획자는 대본을 읽고 어떤 대목을 눈으로 확인하면 뜻이 달라지는지 적는다. 편 전체의 기본 화풍은 그 질문이 반복해서 돌아오는 곳에 맞춘다.

| 화풍과 어울리는 주제 | 이 화풍을 선택할 대본의 단서 | 움직임으로 드러낼 것 | 쓰임이 끝나는 지점 |
|---|---|---|---|
| 캐주얼 셀 애니메이션 · 심리, 인물 일화, 일상의 반전 | 손이 멈추고 다른 곳을 본다. 상대의 표정으로 마음이 바뀐다. | 배경을 고정하고 손의 무게, 먼저 가는 눈, 뒤따르는 고개를 독립적으로 연기시킨다. | 연구 결과의 크기는 인물 표정만으로 읽을 수 없다. 이때는 같은 색과 선으로 비교 대상을 그린다. |
| 그림책·기억 삽화 · 회상, 여행, 생활사 | 지금 겪는 하루와 나중에 떠오르는 하루가 다르다. 어떤 기억이 남았는지가 이야기다. | 추억 하나가 독립된 그림으로 남거나 비슷한 장면들끼리 같은 자리에 포개진다. 인물·소품을 다시 보게 해 앞의 사건을 회수한다. | 현재 일어난 사건을 증명해야 하면 출처 있는 기록을 제시한다. |
| 그래픽 애니메이션 · 권한, 정보 흐름, 보이지 않는 인과 | 누가 무엇을 넘기고 어디서 막히는가. 입력이 같은데 승인 주체가 달라 결과가 달라진다. | 손에 남는 것과 전달되는 것을 동시에 보이고 전달·중단·회수에 각각 의미를 준다. 실제 동작의 근거가 필요한 곳에는 발표나 시연을 붙인다. | 버튼 위치를 가르칠 때는 실제 제품 화면이 필요하다. 개념 재현에는 화면 안에 예시임을 밝힌다. |
| 비실사 2.5D 단면 삽화 · 도시, 산업, 기계 | 물건이 어디에서 조립되는지, 사람의 일터와 생활 공간이 어떻게 연결되는지가 쟁점이다. | 앞뒤 가림, 단면, 고정 시점에 물건이나 사람이 지나가는 경로로 공간의 관계를 읽게 한다. | 환산 소득이나 전망처럼 물리적 형태가 없는 수치는 단위·기간·근거로 돌아간다. |
| 미니어처·입체 캐릭터 · 만들기, 물체의 무게가 중요한 코미디 | 접히거나 끼고, 손이 버티거나 물체가 넘어지는 행동이 다음 사건을 만든다. | 접점·무게중심·반동과 뒤늦게 따라오는 작은 움직임을 그린다. | 물체의 질감이 논점을 가릴 때는 간단한 단면이나 캐주얼 원화를 택한다. |
| 관찰 다큐·자료 편집 · 시사, 시장, 제품 검증 | 누가 언제 발표했거나 어느 수치가 어떻게 달라졌는지 확인해야 한다. | 읽을 위치나 비교할 두 값을 보여 주고 읽는 동안 화면을 둔다. 변화의 순서 자체가 근거일 때만 시간축을 움직인다. | 현장 사진 한 장으로 고용과 소비 사이의 인과를 입증할 수 없다. 분석·개념도는 화면에 구별해 둔다. |

## 제작과 인계

1. 기획자는 승인 대본, 시청자 질문, 핵심 대사의 선택 근거, 한 편의 기준 그림을 저장한다. 레퍼런스에서는 시선, 재질, 깊이, 상태 전환처럼 관찰할 수 있는 기법을 선택한다. 같은 편에서는 인물·선·팔레트·광원·카메라 기준을 이어 쓴다.
2. 편집자는 실제 발화 구간에 대해 대사, 관객이 봐야 할 대상, 시작 상태, 변화를 일으키는 말이나 행동, 도착 상태를 기록한다. 원본이나 통계를 보여 주는 구간은 출처·단위와 정지 이유를 남긴다. 같은 소품이라도 대사가 요구하는 동사가 달라지면 장면을 다시 설계한다.
3. 제작자는 기준 원화를 고정하고 움직일 요소와 배경을 나눈다. 타임라인의 대상·시점·위치·가림·도착 상태를 파일에 저장한다. 이미지 생성 서비스는 원화를 준비하는 선택지다. 이어받을 때는 보관한 원화로 시작한다.
4. 다른 에이전트는 먼저 장면표와 렌더 입력을 읽고 같은 명령으로 재생한다. 파일과 버전·해시를 확인한다. 파일 누락은 해당 장면의 재현 문제로 기록한다. 새로운 해석은 새 판본으로 남기고 기존 원화에 덮어쓰지 않는다.
5. 소리를 끈 채 시작과 끝 사이에서 관객이 **무엇이 어디로 왜 변했는지** 읽을 수 있는지 본다. 음성을 켜고 지시 대상·전환 시점·근거·자막 가림을 다시 본다. 카메라는 시점 이동이 이야기인 경우에만 움직인다. 승인은 사용자가 한다.

이번 세 편에서는 기억을 떠올릴 때는 기억이 남는 과정을, 카드 번호를 걱정할 때는 번호와 토큰의 서로 다른 행방을, 공장 밖의 온기를 말할 때는 일터에서 식당까지 이어지는 경로를 보여 준다. 화풍 선택을 판정할 수 있는 기준은 관객이 그 차이를 화면에서 짚을 수 있는지다.

## 다른 에이전트가 실제 컷을 이어받는 방법

기획과 재생성을 구분한다. 새로운 대본을 각자 읽으면 같은 문서에서도 다른 샷을 설계할 수 있다. S5에서 담당자가 실제 대사, 선택한 레퍼런스의 기법, 시작 자세, 행동을 일으키는 말, 도착 자세, 다음 컷에서 이어받을 대상과 근거 원문을 기록한다. D3에는 서로 이어지는 장면을 영상으로 낸다. 이어받은 담당자는 승인 범위와 판본을 확인한다. 화풍만 승인되었다면 실제 동작과 컷 연결은 검토 중이다.

프로젝트에 고정 편집본이 있으면 **동일한 기본 명령**을 사용한다. `02_script/motion_edition.json`은 실제 컷 순서와 프레임 단위 동작, `02_script/motion_source.json`은 Drive에서 해당 매체 묶음을 찾는 주소다. `edit-plan`은 인계 경로를 안내한다. `hybrid`는 작업 폴더와 Drive의 장면표를 대조하고, 저장소에 있는 렌더러로 원화·동작·기존 음성·자막을 조립한다. 판본 차이는 오류로 표시한다. 새 편에서 일반 하이브리드 형식을 선택했다면 `hybrid.json`이 해당 형식의 렌더 입력이다.

```powershell
$env:YTFLOW_DRIVE = 'G:/내 드라이브/ytflow'
python -m ytflow edit-plan <프로젝트>
python -m ytflow hybrid <프로젝트>
```

고정 장면표의 각 컷에 시작 프레임 `at`, 대사 `words`, 연출 근거 `reason`을 둔다. 출처 화면은 `still`로 지정한다. 합성 컷은 `composition.back`에 기준 배경을, `layers`에 겹침 순서대로 투명 원화와 `keys`를 기록한다. 키 하나에는 컷 안 프레임, 중심 좌표 x·y, 불투명도, 회전이 들어간다. 카메라가 고정된 상태에서 종이, 손, 물건 등 지정한 요소만 변한다. 다음 컷의 첫 자세가 앞 컷 마지막 동작과 이어지는지 검토한다.

매체 묶음에는 편별 `edition.json`, `voice.m4a`, `captions.ass`, 기준 원화와 글꼴이 있다. 컷에서 사용하는 모든 파일을 `input_sha256`에 기록한다. 저장소 렌더러와 글꼴 해시는 `runtime.json`, 그 파일의 해시는 프로젝트의 `motion_source.json`에 기록한다. 검토본은 묶음 안의 해당 편 `review.mp4`에 생성된다. 이번 재편집 묶음은 Drive의 `ytflow/영상/20261118-directed-cut`이다. 검증 환경은 Python 3.13, PyAV 19.0.2, Pillow 12.3.0, libass·libx264를 포함한 FFmpeg 8.1.1이다.
