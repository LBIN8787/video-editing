# 01. 벤치마킹 — 식스시그마 · AI비즈PT · 로제타

> **먼저 밝혀 둘 점**
> 이 문서를 만든 작업 환경에서는 YouTube 접속이 막혀 있었습니다. 웹 검색에서도 세 채널을 확실히
> 특정할 수 없었습니다. '로제타'로는 버튜버 채널만 검색됐고, 'AI비즈PT'는 주언규 PD의
> '비즈니스PT' 교육 쪽 자료만 나왔습니다.
> 그래서 이 문서는 특정 영상을 보고 쓴 분석이 **아닙니다**.
> **① 세 채널에서 무엇을 재야 하는지(측정 틀)**, **② 이 장르(얼굴 없는 지식·비즈니스 해설)에서 흔한
> 패턴을 '검증할 가설'로 정리한 것**, **③ 실제 측정을 자동으로 돌리는 방법**만 담았습니다.
> 실제 수치와 규칙은 `python -m ytflow benchmark --video` 를 돌리면 `data/style_profile.json` 에 채워집니다.

---

## 1. 무엇을 벤치마킹하나: "영상"이 아니라 "제작 시스템"

| 층위 | 질문 | 자동 측정 방법 (ytflow) |
|---|---|---|
| **기획 (소스)** | 어떤 주제가 '채널 평균 대비' 터지나? | 채널 최근 40개의 조회수 ÷ 롱폼 중앙값 = **outlier 배수** |
| **패키징** | 터진 영상의 제목은 무엇이 다른가? | 상위/하위 제목의 길이, 숫자·물음표·따옴표 비율 비교 |
| **대본** | 첫 30초에 무슨 말을 하나? 말이 얼마나 빠른가? | 자동자막 → 훅 원문, **분당 글자 수**, 문장 길이, 질문 빈도 |
| **편집** | 화면이 얼마나 자주 바뀌나? | ffmpeg 장면 전환 감지 → **분당 컷 수**, 평균 샷 길이, 첫 30초 컷 수 |
| **포맷 운영** | 롱폼/쇼츠 비중, 길이 | 길이 분포, 쇼츠 비율 |

이 측정값을 Claude에 넣어 **재현할 수 있는 규칙**(`script` 규칙, `edit` 규칙)으로 바꿉니다.
규칙에는 대사나 제목의 복제를 넣지 않고, **구조·리듬·장치만** 담습니다.

## 2. 채널별 역할

`config/channels.yaml` 의 `role`/`weight` 로 조절합니다.

| 채널 | 역할 | 주로 가져올 것 (가설: 측정으로 확인) |
|---|---|---|
| [식스시그마](https://www.youtube.com/@식스시그마) | **primary** (70%) | 대본 구조, 말 속도, 자막·강조 규칙, 컷 리듬 → 대부분의 기본값 |
| [AI비즈PT](https://www.youtube.com/@AIBizPT) | reference (30%) | AI·비즈니스 주제 선정, 제목 공식, '따라 할 수 있는 실행' 형식 |
| 로제타 | 보류 (주소 확인 후 추가) | (채널을 특정한 뒤 정함) 내레이션 톤, 스토리텔링 방식 |

> 로제타는 주소를 확인하지 못해 `channels.yaml` 에 주석으로만 남겨 두었습니다. 주소가 확인되면 주석을 풀고 weight 를 다시 나누세요.

## 3. 장르 가설 체크리스트 (측정 후 ✔/✘ 표시)

얼굴 없는 한국어 지식·비즈니스 해설 채널에서 흔히 보이는 패턴입니다.
벤치마킹 결과와 비교해서 **맞는 것만** 남기세요.

**대본**
- [ ] 첫 문장에서 결론이나 충격적인 숫자를 먼저 던진다 (결론 선공개형 훅)
- [ ] "왜 ~일까요?" 같은 질문으로 섹션을 연다 (질문 → 근거 → 해석)
- [ ] 섹션 끝마다 다음 내용을 예고한다 (오픈 루프)
- [ ] 분당 300~380자 정도로 빠르게 말하고 문장이 짧다
- [ ] 마지막에 시청자 의견을 묻는 질문으로 끝낸다

**편집**
- [ ] 3~5초마다 화면이 바뀐다 (분당 컷 12~20)
- [ ] 화면 아래에 내레이션 자막을 늘 띄우고, 핵심어 1~2개만 색으로 강조한다
- [ ] 화면 위나 가운데에 큰 글씨(키워드 카드)를 띄운다
- [ ] 자료화면, 차트, 텍스트 카드, 밈을 번갈아 쓴다
- [ ] 내레이션 앞뒤의 무음을 잘라 '쉼 없는' 리듬을 만든다
- [ ] BGM을 작게 깔고, 전환 지점에 효과음을 넣는다

**패키징**
- [ ] 제목에 숫자나 대비(전/후, A vs B)가 들어간다
- [ ] 썸네일 문구는 8자 안팎이고 제목과 겹치지 않는다

## 4. 벤치마킹을 돌리는 법

```bash
pip install -r requirements.txt          # ffmpeg 는 별도 설치
# config/channels.yaml 의 url 3개를 실제 @핸들 주소로 수정
python -m ytflow benchmark --no-llm      # 수치만 먼저 확인 (API 호출 없음)
python -m ytflow benchmark --video       # 컷 속도까지 측정 + 스타일 프로필 생성
```

산출물:
- `data/channels/<채널>/videos.json`: 영상별 outlier 배수 (어떤 주제가 터졌는지)
- `data/channels/<채널>/metrics.json`: 제목, 말 속도, 훅, 컷 통계
- `data/style_profile.json`: 이후 모든 단계가 참조하는 **스타일 규칙 + 수치 목표**

**한 달에 한 번** 다시 돌려 트렌드 변화를 반영하세요. 크론 예시는 `02-workflow-sop.md` 에 있습니다.

## 5. 지켜야 할 선

- 저화질 영상은 컷 수를 잴 때만 내려받고 **분석이 끝나면 바로 지웁니다** (코드가 자동으로 지움).
- 타 채널의 화면, 대사, 썸네일을 그대로 쓰지 않습니다. 대본 프롬프트에도 금지 규칙을 넣었습니다.
- 자막에서 가져온 주장은 리서치 단계에서 `재확인 필요` 로 표시하고, 1차 출처로 확인한 뒤에만 단정합니다.
