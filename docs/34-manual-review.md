# 34. 매뉴얼 정기 검토 — 시키지 않아도 매일 밤 (2026-11-15)

> 사용자: "매번 제가 명령하고 검토시키는 것이 아니라 앞으로 지속적인 검토를 시키고자 합니다."
> 결정: **매일 밤 · 분명한 것만 고침 · 휴대폰 알림 + 그래프**.

## 무엇을 재나 (`python -m ytflow manual-audit` → `manual/audit.md`·`audit.json`)
2026-11-15 손으로 한 매뉴얼 검토(v34)에서 찾은 문제를 규칙으로 옮겼다. 항목마다 **fix**(판단 없이 고칠 수 있음) / **ask**(사용자 판단).

| 종류 | 무엇 | 처리 |
|---|---|---|
| 충돌 후보 | 같은 주제를 '더 하라'·'덜 하라'로 말하는 규칙이 함께 (인용·기록용 절 제외) | ask |
| 과적합 후보 | 스타일·실험 층인데 금지·MUST (사람이 층을 확정하지 않은 것) | ask |
| 반영 대기 | CHANGELOG '반영 대기'가 남음 | ask |
| 층 미정 피드백 | `feedback.yaml` 에 scope 없는 말 | ask |
| 어긋난 해석 | 의도 정렬에서 과잉·덜·다른 뜻·충돌로 판정된 채 남음 | ask |
| 폐지된 기준이 남음 | 순서 예고·고정 인사·'진행 멘트를 넣는다'·소개 → 훅·주말 분석·목소리 미정·`intro` 장면·'카메라가 계속 움직인다'·10분 미만 롱폼 | fix |
| 깨진 참조 | 없는 절(§)·파일을 가리킴 | fix (같은 내용이 없으면 ask) |
| 코드 위치 바뀜 | 용어 사전·의도 판정이 가리키는 코드 줄이 없음 | fix |
| 주제 레포 오류 | 없는 장면 종류·연출 기법을 가리킴 | fix |
| 옛 그래프 | graph.json 이 원본과 다름 | fix |
| 모순 | 장부 `manual/contradictions.yaml` 의 열린 모순 (open → 물어봄, decided → 고칠 차례) | ask / fix |
| 모순 점검 차례 | 지난 점검 뒤 바뀐 지침 파일 · 전체 점검 7일 지남 | fix |

폐지된 기준·깨진 참조는 매뉴얼 밖의 **지침 파일**(AGENTS·README·CLAUDE·skills·prompts·styles STYLE·channels·topics·formats)에도 잰다 (2026-11-20).

지난 검토와 비교해 **새로 생김 / 해결됨**을 남기고, '검토 기록' 표에 날짜별 수를 쌓는다. 폐지 문구 목록은 `ytflow/stages/audit.py` 의 `RETIRED` — 새 기준이 옛 기준을 대체할 때 여기에 한 줄 더한다.

## 모순 관리 (2026-11-20)
> 사용자: "모순되는 지침은 없는지 체크하고 주기적으로 이를 관리 할 수 있도록 해줘"

낱말로 찾는 '충돌 후보'는 매뉴얼 안의 '더 하라 ↔ 덜 하라'만 잡는다. 실제 모순은 주로 **매뉴얼이 바뀌었는데 스킬·프롬프트·채널 설정·정기 작업 지시문이 옛 기준을 말하는 것**이라, 읽고 맞대는 점검을 따로 둔다.
- **장부** `manual/contradictions.yaml`: 모순 한 쌍 = 한 항목 (a·b 위치와 문장, 어느 쪽이 지금 기준인가, 고칠 문장, 상태 open/decided/resolved/kept).
- **매일 밤**: 지난 점검 뒤 바뀐 지침만 맞댐 (audit 이 바뀐 파일을 알려 줌). **7일마다**: 주제별 전체 점검 + 정기 작업 지시문 점검.
- **판정**: 권위 순서(날짜 있는 사용자 원문 > 최신 버전 규칙 > 매뉴얼 본문 > AGENTS > 스킬·프롬프트·스타일·채널 > docs). 낡은 쪽이 분명하면 고치고 resolved, 아니면 open 으로 물어봄. 범위가 다르면 모순 아님.
- **다시 생기지 않게**: 폐지된 기준은 `audit.py` 의 `RETIRED` 에 더해 글자로 자동 감시.
- 절차: `skills/manual-review/SKILL.md` 2-1. 마침 기록: `python -m ytflow manual-audit --checked [--full]`.

## 매일 밤 (정기 작업)
- 22:17 (한국 시간, 매일) 이 작업 세션이 깨어나 `skills/manual-review/SKILL.md` 절차를 따른다:
  잠금 → 최신으로(main 도 합침) → manual-graph → manual-audit → **모순 점검(장부)** → **fix 만 고침** → 다시 재기(`--fixed` 로 고친 것 기록) → 그래프·공유 페이지 갱신 → 커밋·푸시 → main 에 합침 → 잠금 풀기 → 휴대폰 알림.
- 하지 않는 것: 매뉴얼 버전 올리기, 규칙의 층·MUST 바꾸기, 사용자 원문 고치기, 렌더·업로드.
- 시간을 22:17 로 둔 이유: 23시~02시(한국)는 정기 작업이 몰려 늦어질 수 있음, 07:00 시장 영상 제작보다 충분히 앞 (manual/09 §1).
